# 惰性排障与自我观察（两问定位 · 从「自创捷径」读摩擦）

## R — 出处（Reference）

本节方法论出自 Loran Nordgren & David Schonthal《The Human Element》第 6 章（2021；中译《人性阻力》）。
原文依据保存在私有工作区（溯源条目 `f28`、`f24`），不随公开版分发。

## I — Interpretation

本卡是惰性轴的**排障 / 观察端**：不直接选药，而是用两个抓手帮人把「卡住」说清楚，或从自己绕路的行为里读出摩擦点。

- **惰性诊断两问**（f28）：问自己——「**这件事到底难在哪儿？**」「**怎么能让它更省事？**」这两问是惰性轴的总诊断句，会自然把问题路由到两个维度（消耗 / 模糊性）与对应子方法。
- **欲望之路**（f24）：人们在草地上踩出的「人造捷径」——当一件事太复杂、太慢、太费力，人就会**自创捷径和变通方法**。作者把它当作宝贵的**摩擦反馈**：「你总想绕开、总用替代做法」的那一步，正是你的摩擦点。

一句话：**说不清卡在哪，就用两问把「难以执行」问出来；说不清摩擦点，就观察自己在哪一步总想绕路。**

**分流句（让位，须写明）**：本卡**只判能力卡、不单开入口**。f28 两问很泛、靠「路由到子方法」产生增益，f24 是一句观察概念——两者都不构成独立出招，撞福格 `make-it-easy`（降难度）、福格 `prompt-types` / 原子执行意图（时机 / 触发）与本书惰性诊断主卡；故经来源路由入口 human-element 访问。**定位走本书（二维 / 类型学），出招走福格。**

## A1 — Application Example

**⚠ 本书全书没有一处「自己对自己改变」的案例或声明，原书主语一律是「你的受众／人们／村民／用户」。** 下列原书素材**均为对外场景**。凡要落到自己身上，只能写成**明确标记的合成演练**，并注明「**机制同源推断**」，不得冒充作者经历。

**主例 · 两问的出处：肯尼亚氯气分配器**（**对外场景**）：作者交代，扶贫小组先诊断出摩擦点，再想办法把它消掉，随后引出这两问。作者用它说明两问的用法：先问它难在哪（村民要等 20 分钟、要量氯量），再问怎么能更省事（把加氯挪到取水时）。**这是作者的对外干预案例，不是自对己案例。**

**辅例 · 欲望之路＝公园草地上的小道**（f24，**对外观察**）：作者观察公共公园 / 森林里人们**自己踩出来的秃地小径**——不走人行道、抄更短的直线。他把这种「人造捷径」读成用户**想要更简单**的信号。**这是作者对他人行为的观察，不是自对己案例。**

**合成演练（自对己；原书未提供自对己案例，以下为按原书规则设计的演练，机制同源推断）**

- 输入／问题 A（f28）：「我想坚持跑步但做不到。」
- 怎么执行：Q1 是什么让它难（换鞋、出门、天气）→ Q2 怎么更简单（鞋放门口，或改跑步机）→ 路由到「消耗」侧。
- 结论／预期输出 A：指出主要阻碍＋一条简化动作。**按原书规则可复算的演练，机制同源推断。**
- 输入／问题 B（f24）：「我规定自己用一个 App 记录饮食，坚持不了几天。」
- 怎么执行：观察自己**总在哪一步绕开或改用替代做法**——发现总跳过「先拍照再填表」这步直接空着，摩擦点在记录流程。
- 结论／预期输出 B：定位摩擦点（记录流程太繁），据此把流程压成一步。**同上，是演练、非作者原案例。**

## A2 — Future Trigger ★

**1. 用户会在什么情境下遇到这类问题（3–5 条）**

- 想做一件事但就是做不到，想先弄清「到底是什么让它难以执行」。
- 想给一个卡住的行为找一个「更简单」的出口（排障式两问）。
- 说不出自己卡在哪，但**总在做一件事时绕开某一步 / 总用替代做法**。
- 想从自己「总想抄近路」的行为里读出真正的摩擦点。
- 想给三张惰性卡（诊断 / 路线图 / 流线化）做一次入口式排障。

**2. 语言信号（中英双写）**

- 中文：惰性排障／是什么让它难做／怎么让它更简单／我总想绕开这一步／我总用别的做法代替／找不到卡在哪／自我观察。
- English: troubleshooting / what makes it hard / how to make it simpler / I always skip this step / workaround / can't tell where I'm stuck.

**3. 与相邻能力怎么区分**

- **`friction-effort-diagnosis`**（上位·惰性总诊断）：那条用**消耗 / 模糊性二维**给静态定位；本卡用**两问排障**与**行为观察**做入口。
- **`roadmap-clarity`**（同轴·模糊性出招）：本卡只定位 / 排障；那条把事说清楚。
- **`streamlining`**（同轴·消耗侧·步骤级定位）：本卡只读出摩擦点；那条**定位到哪一步**并搬走旁边的障碍。
- **福格 `make-it-easy` / `prompt-types`**（跨书·见分流句）：出招走它们。

**4. 近邻负例（什么样的请求不该触发本卡）**

- 「直接告诉我**怎么把这件事变简单**」→ 不触发本卡，走福格 `make-it-easy`。
- 「我**总忘了做**」→ 走 roadmap-clarity / 福格 `prompt-types`。
- 「帮我把这件事**排进日程**」→ 走福格 `prompt-types` / 原子执行意图。
- 「我就**没动力 / 不想做**」→ 走福格动机诊断。
- 「这件事到底**卡在哪一类阻力**」→ 走 four-frictions-diagnosis。
- 纯信息查询（「惰性诊断两问是什么」）→ 走来源路由入口 human-element。

## E — Execution

### 输入契约

- **必需**：① 一件「做不到 / 卡住」的具体事。
- **二选一（决定走哪条）**：②a 一个**说不清卡点**的抱怨（走两问排障 f28）；②b 一段**最近实际做这件事的过程 / 自己的替代做法**（走欲望之路观察 f24）。
- **缺**必要输入时先问，**不许静默替用户判摩擦点**。
- **适用条件**：惰性轴内的排障 / 观察；纯动机 / 纯时点问题不适用（见 B 段分流）。

### 输出契约

**产出类型**：`diagnosis`（排障 / 观察产物：主阻碍 ＋ 一条简化方向）

- **输出**：① 主要阻碍（是什么让它难以执行）；或 ② 被定位的摩擦点（我总绕开的那一步）；并给**一条简化方向**。
- **完成标准**：能指出一个具体阻碍 / 摩擦点（而不是笼统的「我懒」），并给出一条可照做的简化动作。

### 步骤

1. **分流**：用户给的是**说不清的抱怨** → 走第 2 步（两问）；给的是**一段实际过程 / 替代做法** → 走第 3 步（欲望之路）；若请求是「直接帮我变简单 / 排日程 / 判断动机」→ 按 B 段分流。
   - 完成标准：明确走两问还是走观察。
2. **两问排障**（f28）：问 Q1「这件事到底难在哪儿？」→ 列出具体阻力；问 Q2「怎么能让它更省事？」→ 给一条简化方向。
   - 完成标准：得到「主要阻碍 ＋ 一条简化动作」。
   - 判停点：若阻碍明显落在**模糊性**（不知道怎么做）→ 转 roadmap-clarity；若落在**消耗**（太费力）→ 转 streamlining；若要**具体降难度**→ 转福格 `make-it-easy`。
3. **欲望之路观察**（f24）：回放自己最近一次做这件事的过程，标出**自己绕开 / 将就 / 改用替代做法**的那一步——那就是摩擦点。
   - 完成标准：定位到一个具体的「我总绕开的那一步」。
   - 说明：该产物**依赖自我如实记录**（见 B 段，档 `assertion`，偏弱）。
4. **交回出招**：把定位到的维度 / 摩擦点交给对应卡处理（模糊 → roadmap-clarity；消耗 → streamlining；惰性诊断总入口 → friction-effort-diagnosis）。
   - 完成标准：指明交给哪条线出招。

### 失败处理与回流

- 第 2 步 Q2 答不出「怎么更简单」→ 说明卡点可能在**模糊性**（不是不知道要不要省力，而是不知道怎么做）→ 转 roadmap-clarity。
- 第 3 步回忆不出过程 / 无替代做法 → 退一步做两问（第 2 步）。
- 用户要「直接变简单」→ 转福格 `make-it-easy`。

## B — Boundary

### 不要用（反场景）

- **要具体降难度 / 拆小步** → 福格 `make-it-easy`。
- **纯时点 / 提醒** → 福格 `prompt-types` / 原子执行意图；「总忘了做」→ roadmap-clarity。
- **没动力 / 不想做** → 福格动机诊断。
- **判「卡在哪一类阻力」** → four-frictions-diagnosis。
- **要直接出招（降难度 / 说清路径）** → 福格 `make-it-easy`（降难度）／roadmap-clarity（说清路径）；要**盘出最摩擦的那一步**走 streamlining，本卡只做排障与观察。
- 纯信息查询 → 来源路由入口 human-element。

### 分流句（**本卡只判能力卡、不单开入口**）

f28 撞福格 `make-it-easy`（降难度）与本书惰性诊断主卡 friction-effort-diagnosis；f24 撞「环境 / 摩擦反馈」侧。本卡两条都**不是独立出招**——两问很泛、靠路由到子方法产生增益，欲望之路只是一句观察概念。裁定：**本卡判能力卡，不单开可发现入口，经来源路由入口 `human-element` 访问。定位走本书（二维 / 类型学），出招走福格 `make-it-easy`。**

### 作者警告过的失败模式（反例素材）

- **把「不主动」当态度问题、拒绝排障**（x25）：既不问它难在哪，也就找不到摩擦，行为因模糊 / 消耗而持续不发生（原书说，路径不清楚时行为就很少发生）。
- **越自信越不做摩擦盘点**（x26）：越相信「只要想做就能做到」的人，越容易忽视可能破坏目标的心理摩擦力——正是本卡两问要防的盲区（原文未给出处）。
- **把症状当真因**（x34）：把「太累 / 没时间」这类表层理由（症状）直接当摩擦点，会打偏；两问应继续往下问。

### 作者盲点与待核查

- **f28 两问很泛（此处必须写明）**：原书**没给**固定步骤与分支，它靠「路由到子方法」（路线图 / 流线化）才产生任务增益——是**总入口而非独立方法**。**不得把两问当成能独立出招的完整方法。**
- **f24 产物偏弱（档 `assertion`）**：欲望之路是**单句观察概念**，无步骤、无出处；其产物（摩擦点）**依赖自我如实记录**，是否算「可检验结果」偏弱。用时须明标。
- **数字未给出处**：f28 所引的氯气分配器（约 10%→61%）**原文未给出处**（点名 Michael Kremer 但无文献）。
- **全书无一处「自己对自己改变」的案例或声明**：本卡的自我场景是**机制同源推断**到自对己，不是作者给的自我场景。

### 相邻易混

- friction-effort-diagnosis：本卡是排障 / 观察入口 / 那条是**二维静态定位**。
- roadmap-clarity：本卡只定位 / 那条出招说清路径。
- streamlining：本卡只读出摩擦点 / 那条**定位到哪一步**并搬走障碍。
- 福格 `make-it-easy`：本卡排障 / 它出招降难度。

## 相关能力

- **friction-effort-diagnosis**（组合）：本卡的两问 / 观察是惰性诊断的**入口式抓手**；那条是二维静态定位。
- **roadmap-clarity**（对比）：本卡只定位 / 排障，它出招说清路径。
- **streamlining**（对比）：本卡只读出摩擦点，它定位到哪一步并搬走障碍。
- **福格 make-it-easy**（对比·跨书，分流句）：本卡排障、读摩擦点，**出招（降难度）走福格 make-it-easy**；本卡判能力卡、不单开入口。
