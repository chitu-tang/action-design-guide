# 参考点管理与多选项（把单死命令扩成一组都能接受的方案）

## R — 出处（Reference）

本节方法论出自 Loran Nordgren & David Schonthal《The Human Element》第 1 章与第 4 章（2021；中译《人性阻力》）。
原文依据保存在私有工作区（溯源条目 `f14`、`p01`），不随公开版分发。

## I — Interpretation

本卡是**惯性轴的第二侧面——参考点管理**。机制一句话：**只给一个选项时，参考点就是现状，现状会赢；给出多个选项，注意力才从现状移开**。所以从单侧的「别只给一个选择」推出动作：**造多个（可接受的）参考物**。

本卡把这条机制落成两个可操作件：

1. **参考点管理 / 多选项**（p01）——把一条「唯一死命令」（如「每天都得跑」）改写成**一组自己都能接受的替代方案**，不再只和「完全不做」的现状比。
2. **把「相对论」落到流程的四步时间线**（f14）——发现问题 → 收集潜在方案 → 确定最适合的方案 → **向受众推荐**。作者指出错误常发生在第 3、4 步：习惯先剔除不好的方案，又会因怕被要求太多而**放弃最理想方案**，只给一个「不错」的选项，使人无从比较。

自我场景要改一处主语：f14 第 4 步本是把方案推荐给受众（对外动作），**改成「把选好的方案写成对自己可行的路径」**（f14 判「需改造」）。

一句话：**别用一条死命令把自己（或受众）逼到只能跟现状比；摆开多个都能接受的参考物，再选一条路径。**

**底子说明（见 B 段）**：参考点管理的底层机制是行为经济学的 **anchoring / decoy**，本书并未把它写成独占概念——它**更可能撞上 Nudge 里的说法**，使用时按重叠登记，**不得当本书独有**。

## A1 — Application Example

> ⚠ **原书未提供「自己对自己改变」的案例**；以下原书案例均为**对外（销售 / 管理）场景**，自我场景一律写成**明确标记的合成演练 + 机制同源推断**。

**辅例 · 垃圾处理公司提供 1/3/5 年合同**（c43）：公司把单一选择改成 1 / 3 / 5 年三档，客户纷纷转向 3 年期——**「感觉是相对的」**。**对外销售场景。**

**辅例 · 作者自露的一处冲突**：同一故事的注解主张始终要摆出最理想的方案，与同章把最理想方案当作该先剔除的说法**前后不一致**（x68）。**这是本卡 B 段点名的存量风险，不得当可用依据。**

**合成演练 A · 把「每天都得跑」改成多方案（p01，原书未提供自对己案例，以下为按原书规则设计的演练，机制同源推断）**

- **输入/问题**：「我想让自己开始每周跑步，但只给自己留了一条死命令『每天都得跑』，两周没动。」
- **怎么执行**：按 p01 把唯一选项改写成一组都能接受的方案。
- **复算**：列成「每周跑 3 次／每次 20 分钟」「隔天快走+慢跑」「周末一次长跑」等 3 个都接受的方案。
- **结论/输出**：不再只和「完全不跑」的现状比较，得到一个可选清单。**机制同源推断，非作者背书。**

**合成演练 B · 转行四步时间线（f14，原书未提供自对己案例，以下为按原书规则设计的演练，机制同源推断）**

- **输入/问题**：「我想转行但拖了很久。」
- **怎么执行**：按四步走，第 4 步「向受众推荐」改造为「把选定方案写成自己可行路径」。
- **复算**：①发现问题（现职成长停滞）→②收方案（内部转岗/外部投递/自由职业/读研）→③选最适（**注意别过早砍掉「最好但不现实」的选项**，如读研；剔掉不可行项）→④写成路径（3 个月内投 20 家）。
- **结论/输出**：得到一条选定路径。**机制同源推断，非作者背书。**

## A2 — Future Trigger ★

**1. 用户会在什么情境下遇到这类问题（3–5 条）**

- 只给自己留了一条「必须……否则就是失败」的死命令，结果动不了。
- 选方案时总是只留一个「还不错」的项，事后又觉得亏。
- 想给自己（或别人）摆出几个都能接受的选择，而不是非此即彼。
- 意识到问题是「跟现状比一定输」，想管理这个比较的参考点。
- 计划太单一、没有退路，想扩成一组可行方案。

**2. 语言信号（中英双写）**

- 中文：只给一个选择 / 死命令 / 非此即彼 / 没有退路 / 多给几个方案 / 我都能接受 / 参考点 / 参考物 / 和什么比 / 一切都相对 / 择优。
- English: only one option / all-or-nothing / give alternatives / multiple acceptable options / reference point / referent management / anchoring / relative comparison / trade-offs.

**3. 与相邻能力怎么区分**

- **`familiarization`**（同轴 sibling，**不适用改走它**）：那是**把陌生变熟悉**（反复接触 / 从小渗透 / 贴原型 / 类比）；本卡是**管理参考点 / 造多选项**。惯性轴两个侧面，产物不同。
- **福格 `anchor-matching` / 原子 `cue-design`**（跨书对比）：**时间挂钩 / 线索显眼**，与本卡的「参考点」不是一回事。
- **Nudge 的 `anchoring` / `decoy`**：参考点管理的底子在那里；本卡**不得写成本书独占**，按重叠登记。
- **`friction-effort-diagnosis`**（对比）：太难 / 太模糊（惰性），不是参考点问题。

**4. 近邻负例（什么样的请求不该触发本卡）**

- 【vs familiarization】「新做法太陌生，帮我先适应一下」→ 走 familiarization。
- 【vs 福格 `anchor-matching`】「给新习惯找个固定时间锚点」→ 走 `anchor-matching`。
- 【vs 原子 `cue-design`】「把提示弄得显眼」→ 走 `cue-design`。
- 【vs Nudge 侧】「我要设计默认选项 / 助推」→ 本卡不接（底子在 Nudge，且不写成本书独占）。
- 【vs 路由入口】「参考点 / 相对论是什么」→ 走来源路由入口 human-element。

**分工说明（本卡 ↔ `familiarization` ↔ 福格 `anchor-matching`）**：**管理参考点 / 把单个选项扩成多个可接受方案** → 本卡；**降低陌生感** → familiarization；**挂时间锚点 / 让线索显眼** → `anchor-matching` / `cue-design`。

## E — Execution

### 输入契约

- **必需**：① 一条**唯一死命令 / 单一选项**（如「每天都得跑」「只投这一家」），或 ② 一组**待选方案**（用于四步时间线）。
- **可选**：各方案的接受度排序、当前默认的「现状」是什么。
- **缺①或②时先问**是哪件事；**不许静默替用户造选项**。若请求其实是「熟悉化 / 时间锚点 / 线索显眼 / 助推」→ 按 B 段分流。

### 输出契约

**产出类型**：`patch`（把单死命令扩成多方案）

一份**候选集 + 一条选定路径**：
1. **≥2 个自己都能接受的替代方案**（p01；不是「选项 A 或什么都不做」，而是都接受的方案）；
2. **一条按四步时间线选出的可行路径**（f14；第 4 步已由「向受众推荐」改为「写成对自己可行的路径」）。

**完成标准**：候选 ≥2 且每个都是当事人能接受的（不是凑数的坏选项）；选定路径写明「何时/做到什么程度」；自评「不再是死命令、有得选」。

### 步骤

1. **先找现状参考点**：问「现在这条死命令，让我在跟什么比」→ 多半是「和完全不做比」。
   - 完成标准：指名现状参考点。
2. **造多选项**（p01）：把唯一选项改写成 **≥2 个都能接受**的替代方案。
   - 完成标准：候选集里没有「明显不能接受的凑数项」。
3. **走四步时间线**（f14）：发现问题 → 收集方案 → **定最适（显式检查有没有过早砍掉「最好但不现实」的选项）** → 改造第 4 步为「写成对自己可行的路径」。
   - 完成标准：得到一条选定路径；第 3 步的「是否过早剔除」有明确记录。
   - **判停**：若发现真正的卡点是「不知道怎么做」→ 转惰性轴 roadmap-clarity。
4. **交回落地（可选）**：把候选集与选定路径写进已有计划的「候选」字段（`patch`）。
   - 完成标准：指明写进哪个计划。

### 失败处理与回流

- 第 2 步写完候选仍只对现状「完全不做」可比 → 检查候选是否真的都被接受；若都不被接受，说明动机/代价问题，转对应轴。
- 第 3 步若反复出现「总想砍到只剩一个」→ 见 B 段 x68，本卡不替作者裁定「该不该保留最理想方案」。

## B — Boundary

### 不要用（反场景）

- 要把新做法**变熟悉** → familiarization。
- 要找**时间锚点 / 触发时机** → 福格 `anchor-matching` / `prompt-types`。
- 要**让线索显眼** → 原子 `cue-design`。
- 卡点是「太难 / 太模糊」→ 惰性轴（friction-effort-diagnosis / roadmap-clarity）。
- 要设计**默认选项 / 助推** → 本卡不接。参考点管理的底子是行为经济学的锚定与损失厌恶（Nudge 侧已以此为原则来源），本卡只做**参考点的置换**（换一个跟谁比），不做选项设计。
- 纯信息查询（「参考点 / 相对论是什么」）→ 来源路由入口 human-element。

### 作者警告过的失败模式（反例素材）

- **过早剔除、放弃最理想方案**：习惯先剔除不好的方案，又因怕被要求太多而**放弃最理想方案**，只给一个「不错」的选项，受众无从比较。
- **只给一个选择→现状赢**：单一选项时参考点就是现状，熟悉的一方往往胜出。**自我版：一条死命令就是在拿它跟旧习惯比，必输。**

### 作者盲点与待核查（不许假装有）

- **主张前后不一致（x68）**：注解处主张始终要摆出最理想的方案，而同章第 3 步却把最好但不现实的方案列入该先剔除的一类、又把放弃最理想方案说成常见错误。**到底该不该保留最理想方案，作者两处口径冲突、边界未厘清**。本卡**只把冲突登记在此，不替作者收口、不假装有判据**。
- **本卡两条成员均是最弱证据档 `assertion`**：f14（「把相对论用于创新的 4 步时间线」）是**类比式主张 + 通用流程壳**，本书特有部分无可追溯支撑，**判据 1 不过**；p01（「始终提供多种选择」）是**由惯性概念推出的一句主张、动作偏薄、无独立步骤与完成标准**，**判据 2 不过**。**用时按最弱档对待，不得拔高。**
- **它为什么仍是一张独立卡（不是可删的重复件）**：f14（四步时间线，判据 1 不过）与 p01（多选项规则，判据 2 不过）是惯性轴上「参考点管理」这一侧面的两个落点——p01 给规则、f14 给流程壳；**同轴的 `familiarization`（熟悉化）与它们产物不同、不可合并**（同轴不同产物）。**它是本书最弱的一张**，保留为一张独立卡，只为给「参考点怎么管」这一请求一个归属；压力测试须单独点名。
- **底子是 anchoring / decoy，更可能撞上 Nudge，不得写成本书独占**：参考点管理的底层是行为经济学的 anchoring / decoy。**本卡不声称这套机制是本书原创**；本卡与 Nudge 的参考点 / 默认侧可能重叠，边界后续再定。
- **f14 判「需改造」**：原书第 4 步本是**对外动作**（向你的受众推荐方案），自我版须改成「把选好的方案写成对自己可行的路径」（需改造之一）。
- **全书无一处「自己对自己改变」的案例或声明**：本卡 A1 已把原书案例标为**对外场景**，自我场景一律写成**明确标记的合成演练 + 机制同源推断**，**不得写成「作者要你对自己这么用」**。
- **task-06（相对论的 2 个技巧：增加极端选项 / 强调不理想选项）未通过核验，其边界归本卡**：增加一个极端选择、强调不理想选项（含诱饵效应）只有参考资料、**没有一条通过核验**（因它是推销策略、只对劝别人成立）。**本卡不承载这两个技巧、不产其能力**；**「强调不理想选项」与「诱饵效应」的界线作者自认只靠诚信、无判据**，不得假装有判据。
- **缺判据**：全书**没有**「什么时候该放弃 / 什么情况不适用」的判据；本卡不假装有。

### 相邻易混

- familiarization：**参考点管理 / 多选项**（本卡）vs **把陌生变熟悉**（它）——惯性轴两个侧面。
- 福格 `anchor-matching` / 原子 `cue-design`：**参考点**（本卡）vs **时间锚点 / 线索显眼**（它们）。
- Nudge：anchoring / decoy 的地盘（它）vs 本书的「多选项规则」（本卡，重叠登记、非独占）。
- friction-effort-diagnosis：**太难/太模糊（惰性）**（它）vs **参考点问题**（本卡）。
