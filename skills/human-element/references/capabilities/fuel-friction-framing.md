# 推动力与摩擦力框架（燃料侧总纲）

## R — 出处（Reference）

本节方法论出自 Loran Nordgren & David Schonthal《The Human Element》第 1 章与第 2 章（2021；中译《人性阻力》）。
原文依据保存在私有工作区（溯源条目 `f01`、`f05`），不随公开版分发。

## I — Interpretation

本卡是本书的**立论层 / 总纲**，它不讲四格怎么填，只定两件事：

**一、方向：任何「让新想法落地」的努力，都同时受两种相反的力。** 一种是把事情往前推的**推动力（Fuel）**，一种是拦住它的**摩擦力（Friction）**。子弹飞得又远又准，不只因为火药足，还因为外形被优化过、减少了空气阻力。同理，一个想法能不能落地，也取决于推力能不能压过摩擦。**默认只加推力、不去减摩擦，是大多数创新者的共同错误**——而且是本书要推翻的那个默认操作：跟着直觉「多讲一遍价值、多加一点好处」，反而在无意中加大阻力（见 B 段 x01）。

**二、分类：推力_**不等于**_吸引力。** 作者把 Fuel 定义得比「吸引力」更宽——它包含两类作用相反的推力：**循序渐进式推动力**（提升吸引力与说服力，传统的 4P / 7P 营销手段，带来乐观与兴奋）与**令人反感的推动力**（靠强调「再不行动的风险与代价」刺激改变，引发担忧、怀疑、焦虑，例如恐惧、损失、风险、后悔、厌倦）。两类都以未来为重点，但后者是「怕做错」而不是「想做强」。本卡只取其中不依赖边界的一步：**先识别自己（或对方）正在用哪一类推力**。

一句话：本卡是「别只看燃料、要看阻力」这一诊断方向的入口，为四格诊断（four-frictions-diagnosis）引路；它**本身不产出一步可执行的干预**，也不替代任何一张诊断 / 出招卡。

## A1 — Application Example

**主例 · Flyhomes 加满推力却无人成交**（`nature: 作者转述的第三方长案例`，c113）——**这是对外场景（一家公司推它的产品），不是自对己案例。**

- **输入/问题**：Flyhomes 想吸引购房者。第一次尝试是加一个「推力」：不发现金返还，改成**买房送航空里程**（买 50 万美元的房子约得 80 万千米里程）。
- **执行结果**：推力确实见效——捷蓝航空群发邮件当天，注册量暴涨、一天新增数千用户；创始人一度以为「就是这样了」。
- **结论/输出**：但推力只把人拉到了注册入口，几乎没人在它这里真正买房。创始人加格自述，激励措施把人拉到了平台上，他们最后却并不在这儿成交，想必另有原因——真正要处理的是买家「在竞争市场买不到房」的摩擦，而不是继续加推力。
- **注**：案例里的数字（80 万千米、一天新增数千、21 亿美元等）**原文未给出处**（c113 备注）。此例演示的正是本卡的立论：**推力在场、摩擦才是真问题**。

**合成演练（自我场景）· 靠「打鸡血」推自己写论文**——**原书未提供自对己案例，以下为按原书规则设计的演练（机制同源推断）**：同一套框架，把主语从「受众」换成「我自己」——
- 我在用哪类推力？一直用「再不写完就毕不了业」这类**令人反感的推力**自逼（怕做错），而不是讲清「写完能怎样」。
- 这件事卡在推力侧还是摩擦侧？降低「每天必须先读五篇文献才能动笔」的启动门槛（摩擦侧）才是关键。
- 预期输出：改用正向、可执行的下一步（先只写一段），并优先压摩擦。此演练**能按原书框架复算**，但原书**未提供**该自我场景的结果，结局属预期、非书证。

## A2 — Future Trigger ★

**1. 用户会在什么情境下遇到这类问题（3–5 条）**
- 一直在给自己 / 别人「打鸡血、讲好处」，却怎么推都不动。
- 正在用恐惧、死线、羞耻式自逼催自己（或团队），开始怀疑这条路对不对。
- 想先判断这件事到底是「推力不够」还是「摩擦太大」，再决定往哪使劲。
- 发现自己反复解释「为什么值得做」，却从不回答「怎么做」。
- 有个「无可挑剔」的想法 / 计划，接受度却上不去，想知道问题出在哪一侧。

**2. 语言信号（中英双写）**
- 中文：推力 / 摩擦力 / 推动力 / 燃料 / 吸引力不够就再加吸引力 / 只加推力 / 加把劲 / 打鸡血 / 两类推力 / 是不是我在用恐惧逼自己。
- English: fuel vs friction / push vs drag / just add more motivation / attraction isn't enough / two types of fuel / am I pressuring myself with fear / the fuel-friction model.

**3. 与相邻能力怎么区分**
- 与 four-frictions-diagnosis：那条**往下走**——把一件事按四格过一遍、指认主摩擦、分流；本卡**停在方向层**——只回答「别只加推力，先看摩擦」「我在用哪类推力」，不产出四格判断。
- 与福格 `make-it-easy` / `prompt-types`：本卡只做「方向前导」，降难度、选提示这些**出招**走福格。
- 与本书三张轴卡：本卡不定位到具体轴，指认到轴是 four-frictions-diagnosis 及轴卡的事。

**4. 近邻负例（什么样的请求不该触发本卡）**
- 「帮我把这件推不动的事按四格诊断一下、告诉我卡在哪」→ 不触发本卡，走 four-frictions-diagnosis。
- 「帮我把这个习惯拆到多小 / 只让它变简单」→ 不触发本卡，走福格 `tiny-habit-design` / `make-it-easy`。
- 「按四种摩擦填一张表」→ 走 friction-report-worksheet。
- 「这本书讲了什么 / 整套模型是什么」→ 走来源路由入口「人性阻力」。

## E — Execution

### 输入契约
- **必需**：一个「推了却没动」的改变（对自己 / 对别人），并说清目前**已经在用什么方式推**（讲好处、给报酬、施压、打鸡血等）。
- **可选**：这件事的目标受众（是自己还是别人）。
- **适用条件**：用户要的是**方向判断**（别只看燃料）。若实际是「按四格诊断一件具体的事」「把它变简单」「填表」，按 B 段分流。
- 缺「推不动的是哪件事」时**先问**，不许静默替用户编。

### 输出契约

**产出类型**：`none`（总纲讲解，不写档案）

可检查产物：
1. **一句方向判断**：这件事更可能卡在**推力侧**还是**摩擦侧**（并说明为什么不是「再加推力」）。
2. **一句推力分类**：指出当事人（我 / 对方）正在用的推力属于**循序渐进式**还是**令人反感的**。
3. **（可选）一条引路**：若要继续深挖，指向 four-frictions-diagnosis 做四格诊断。

**完成标准**：用户能说出「这事要往摩擦侧看，不要只加推力」，并说得出自己现在用的是哪一类推力。

### 步骤

**第 1 步 · 分侧（推力侧还是摩擦侧）**
- 动作：问「现在试过的办法，是在加推力（讲价值、给好处、施压）还是在减摩擦（降门槛、清障碍、补方法）？」据此判方向。
- 完成标准：给出「更可能卡在摩擦侧」的判断，并能说出为什么不继续加推力。
- 判停：若用户其实已给了具体的事、要**定位到哪一根摩擦轴**，转 four-frictions-diagnosis。

**第 2 步 · 识别在用的哪类推力**
- 动作：把当事人现在用的推力归类——**循序渐进式**（讲好处、提吸引力）还是**令人反感的**（讲不做的代价、恐惧、死线、羞耻）。只做识别，不对「两类推力的边界」下判据（边界作者没说清，见 B 段）。
- 完成标准：明确说出「现在用的是哪一类推力」。
- 判停：若发现一直在用**令人反感的推力**自逼 / 逼人，提示「这类推力往往会引发焦虑与抵触」，指向对应轴卡（情感 / 抵触）——但本卡不出招。

## B — Boundary

### 不要用（反场景）
- 要按四格**诊断**一件具体推不动的事 → four-frictions-diagnosis。
- 要**一张填好的四格表** → friction-report-worksheet。
- 要把习惯建起来 / 拆小 / 降难度 / 加提示 → 福格 `tiny-habit-design` / `make-it-easy` / `prompt-types`。
- 只想了解整本书 / 整套模型 → 来源路由入口「人性阻力」。
- 对外说服术 / 销售话术 → 本书不做。

### 作者警告过的失败模式（反例素材）
- **默认只加推力、不减摩擦**（x01）：跟着直觉增加更多推动力，反而在无意中给创新添了阻力；一个想法价值再高，也不会因此减小它受到的摩擦。
- **把「吸引力」当成「燃料」的全部**：Fuel 比吸引力宽，还包含令人反感的推力；只盯吸引力会漏掉「靠恐惧 / 代价推动」这一路。

### 作者盲点与待核查（写进卡、不许假装有）
- **f05 两类推力的边界作者没说清（硬标识）**：原书只给出「分两类」，**没有给判断「何时算循序渐进式、何时算令人反感的」的判据**。本卡因此**只用「识别我在用哪类推力」这一不依赖边界的用法**，不假装有边界判据；若有人要求边界判据，如实说「作者未给」。
- **f01 是类比、无数据（硬标识）**：子弹双力是贯穿全书的**类比壳**，无可独立执行的步骤与完成标准，证据档是最弱档 `assertion`。本卡不把它讲成有数据的结论。
- **全书无出处体系**：凡引数字一律「原文未给出处」；本卡所引段落本身为类比与分类，不含数字。
- **证据档四档具名**：f01 ＝ `assertion`（类比）；f05 ＝ `author_firsthand`（作者自设的分类框架，但有边界缺口，从严可作 `assertion`）。**不写 `strong` / `medium` / `weak`**。
- **四摩擦的英文原词不在中文正文**：Fuel（推力）与四摩擦（Inertia / Effort / Emotion / Reactance）的英文系从英文原著侧核得，**中文正文里没有这些英文词**；「摩擦 / 心理摩擦力」是四摩擦的统称，不是第五个要素。
- **全书无一处「自己对自己改变」的案例或声明**：原书主语一律是「你的受众 / 人们 / 球员 / 选民」（x65）；本卡 A1 的自我场景是**明确标记的合成演练**，属**机制同源推断**，不是作者原意。

### 相邻易混
- four-frictions-diagnosis（对比）：本卡是方向前导（别只加推力）；它是四格诊断的落点。
- 福格 `make-it-easy` / `prompt-types`（跨书，出招）：本卡只分侧、只识别推力类型；降难度、选提示走福格。
- friction-effort-diagnosis（对比）：本卡是总纲层；它是惰性轴的诊断主卡。

## 相关能力

- **four-frictions-diagnosis**（对比）：本卡是它的方向前导——先「别只加推力、先看摩擦」，再按四格指认主摩擦、分流到各轴卡；本卡停在方向层、不产出四格判断。
- **friction-report-worksheet**（组合）：本卡是总纲方向层，它把四格诊断落成一张可填的表（经来源路由入口访问）。
- **福格 make-it-easy**（对比·跨书）：本卡只做「推力 vs 摩擦力」的分侧与推力类型识别；真正降低难度、拆小步的动作走福格。
