## I — Interpretation

这是一张**可按需组合的话术矩阵**：**4 个观察角度（列）× 8 个力度/时间尺度（行）= 32 格**，每一格是一句针对性的肯定消息。

用途：当某个人（团队成员 / 家人 / 同事）做出值得肯定的行为时，先看**语境**选一个「观察角度」（从哪个侧面去肯定），再选一个「力度/时间尺度」（肯定到什么程度、放在哪个时间尺度上），两者交叉即得该格对应的一句话。

作者的关键提醒是：**这 32 种对每个人的影响力并不相同**——有人吃「你自己的表现本身」的反馈，有人吃「与同伴比较」的反馈，少数人在表现不佳时也想听好消息。所以这张矩阵不只是「给话」，更是用来**识别哪类肯定能为对方创造最多的 Shine（发光）点**，据此帮助对方感受成功、巩固习惯、提升表现。

矩阵围绕**销售业绩**举例。例如：列 1「你的出色表现」× 行 B「最棒的一次」= 「本周你创造了个人最佳成绩，卖出的配件比以前任何时候都多」；若改取列 4「表现不佳也有好消息」× 行 H「勇于接受挑战」= 「虽然没有卖出任何配件，但你也没有因此而退缩」。

它本质是一个**对照表/生成器**：输入 = 人物语境 + 所选角度（列）+ 所选力度（行）；输出 = 一句对症的肯定消息；可反复生成。它与 `c72`（32 种肯定成功的方式，example 类）是**同一张表 9-1 的两面**——`f55` 是框架面、`c72` 是示例面（只建链接，不合并）。

## A1 — Application Example

**示例（作者原书框架样例，同表 9-1，`c72`）：给一位销售员发一条肯定消息。**

- **输入/问题**：一位销售员本周创造了个人最佳成绩，要直接给 TA 发一条对症的肯定，而不是泛泛地说「干得好」。
- **怎么执行**：
  1. 定语境——对方做得好，且这是「最好的一次」。
  2. 选列——取列 1「你的出色表现」（聚焦对方自身表现）。
  3. 选行——取行 B「Best ever 最棒的一次」。
  4. 查表得该格句子：**「本周你创造了个人最佳成绩，卖出的配件比以前任何时候都多」**。
  - 换一组坐标演示矩阵性：取列 4「表现不佳也有好消息」× 行 H「勇于接受挑战」→「虽然没有卖出任何配件，但你也没有因此而退缩」。
- **结论/预期输出**：一句对症的肯定消息 + 所选 `{列, 行}` 坐标。可按语境任意选角度 × 力度生成句子，与预期一致。
- **结果**：原书以这两格作为**框架示例**呈现，**未交代被肯定者的实际反应**（标「未说明」）。

## A2 — Future Trigger

**1）用户会在什么情境下遇到这类问题（3–5 条具体场景）**

- 要给团队成员/家人/同事发一条**肯定或鼓励的话**，但不知怎么说才不空洞、不伤人。
- 想按**具体语境**生成一句对症的肯定（对方刚达成里程碑 / 只是持续努力 / 表现其实不好但仍值得肯定）。
- 想知道**哪一类肯定/反馈对某个人最有效**，好让对方真正「感受到成功」。
- 在做群体反馈设计（`group-behavior-design` 第 6 步），手上有一个「该给正反馈」的场合，缺一句具体的话。

**2）语言信号（中英双写关键 trigger）**

- 中文：怎么肯定某人 / 表扬 / 鼓励 TA / 怎么说这句话 / 发条鼓励的话 / 怎么夸才不别扭 / 给 TA 一句反馈。
- English: give positive feedback / how to praise / how to compliment a teammate / affirmation message / encourage someone / 32 ways to give positive feedback.

**3）与相邻能力怎么区分**

- **主体是「我」自己（自己给自己庆祝/奖励）→ `celebration`**（自我庆祝机制与规则）。**主体是「给别人的肯定」→ 本卡**。凡肯定对象不是用户本人，才触发本卡。
- `group-behavior-design`：那张卡是群体**整体 7 步流程**（第 6 步「庆祝成功以巩固习惯」只是其中一环）；本卡是第 6 步反馈环节的**侧翼工具**，只在「给我一句对症的肯定」时用。
- `c72`（支撑侧，example）：与本卡同表 9-1 的**示例面**，只建链接不合并。

**4）近邻负例（什么样的请求不该触发本卡）**

- **【vs `celebration`】**「我做完微习惯想给自己一个庆祝方式 / give myself a celebration」——这是**自我**庆祝 → **不触发本卡**，走 `celebration`。
- **【vs `group-behavior-design`】**「怎么让员工长期坚持步行挑战 / how do I get my team to stick with this challenge」——这是群体**整体设计**，不能只按肯定话术矩阵处理 → **不触发本卡**，走群体设计卡。
- **【vs 晋级技能】**「我自己想改掉一个坏习惯 / help me quit」——改变对象是用户自己 → **不触发本卡**。

## E — Execution

**输入契约**

- 必需三项：① **被肯定的人 + 语境**（做了什么、表现处于哪一档）；② 从 4 列里选定的**观察角度**；③ 从 8 行里选定的**力度/时间尺度**。
- 缺 ① / ② / ③ 任一项要先问或先与用户确认，不许静默猜值。
- 适用条件：对象是**别人**（不是用户自己给自己庆祝）；场景是「有事要肯定」的正反馈。

**步骤**

1. **定语境。** 写下对方做了什么、表现处于哪一档（好、最好、比上次好、达成里程碑、趋势向好、一贯努力、本可能更糟、顶住挑战）。
   - 完成标准：能用一句话描述事实与档位。
2. **选列。** 从 4 个观察角度选 1（`1. 你的出色表现 / 2. 与别人相比你的表现 / 3. 合作时的表现 / 4. 尽管表现不佳也仍有好消息`）。**慎重选**——尽量选对方在意的角度（参见 `f54` 强力区）。
   - 完成标准：说出所选列及理由。
3. **选行。** 从 8 个力度/时间尺度选 1（`A. 一次 / B. 最棒的一次 / C. 与上次相比 / D. 达成里程碑 / E. 趋势向好 / F. 一贯努力 / G. 本可能更糟 / H. 勇于接受挑战`）。
   - 完成标准：说出所选行及理由（与第 1 步的档位一致）。
4. **产出句子。** 取该格（列 × 行）对应的肯定消息。
   - 完成标准：产出一句具体、对症的肯定，而不是「做得好」这类泛泛之语。
5. **校验。** 这句话是否真诚、是否聚焦赋能而非否定（避免在对方脆弱处挑毛病，见 `x43`）。
   - 完成标准：通过「真诚 + 赋能」两项检查。

**输出契约**

- 一句对症的肯定消息 + 所选 `{列, 行}` 坐标。
- 完成标准：能说清「为什么选这个坐标」（依据 = 对方在意的角度 + 实际表现档位）。

## B — Boundary

**反场景（不要用本卡）**

- 只给自己庆祝/奖励时 → 走 `celebration`。
- 要设计整个群体的 7 步方案时 → 走 `group-behavior-design`；本卡只在「需要给一句对症肯定」时作为侧翼工具。
- 用户的诉求是「怎么让对方别做某事 / 怎么指出问题」→ 这不是肯定；若涉及负面反馈落在对方脆弱处，见 `x43`（强力区的阴影），不该硬套本卡。

**证据级别 / 引用级别（低一档，务必看见）**

- 本卡唯一依据是**附录表 9-1**。中文侧该表原先只能靠**插图转录**取得（只读一次图、未做交叉核验）；**英文版把同一张表以逐字文本印出**，据此逐格回核得 **32/32 格全对、4 个列标题全对、8 个行标全对，0 处差异**——可信度由「单次读图 / 同模型复读」**升级为「经独立第二来源确认」**。但按本册既定口径，仍**按侧翼工具处理**（触发面窄 + 证据低一档）。
- **本卡 R 段直接取英文版附录正文，不用插图转录**；后续仍可抽样回原书附录原图比对。
- 五判据纸面全过，但五判据里**没有「证据强度」这一维**——本卡的降级只能由人补（`CONSOLIDATED` §5 已记）。

**版权约束（必须写清）**

- **32 格的具体句子是作者的实质内容**：**内核层可引用**（本卡 R / A1 段的少量示例属于内核层用法），**公开层 / 对外交付不得搬运** 32 句原文——对外只能给「4 列 × 8 行」的结构与自撰示例。

**作者未给判据的地方**

- 作者只说「不同的人反应不同、我的研究表明……」，**没有给出「怎么判断对方属于哪一类」的可执行方法**。需要时用情境试探，不要把「某人吃哪一类」当作已知。

**相邻易混**

- 与 `celebration`（自我庆祝机制/规则）区分：那张卡管「自己给自己庆祝」，本卡管「给别人的肯定」。
- 与 `group-behavior-design` 第 6 步区分：那张卡是群体整体流程，本卡是其中反馈环节的工具。
- 与 `c72`（同表示例面）只建链接不合并。
- **证据级别提醒**：本卡 `importance` 是 `medium`、且证据在册内低一档，别把它当成与 `group-behavior-design`（`f52`）同等硬度的群体设计主卡使用。
