## R — 出处（Reference）

本节方法论出自 B.J. Fogg《Tiny Habits》第 8 章（2020；中译《福格行为模型》）。原文依据保存在私有工作区（溯源条目 `p86`），不随公开版分发。

出处说明：中文版把这两条称作「福格原则 1 / 2」，但英文原书用的词是 **`Maxim`**（**不是** `Fogg Principle`，原书无此词）。两条的正式英文名见原书第 6 章与第 9 章；合集标题作 `Maxims` / `Fogg Behavior Maxims`。

---

## I — Interpretation

这是「改变他人」这件事上**可执行的伦理核对清单**。两条 maxim 是：

1. **`Fogg Maxim #1`**——帮人们做**他们本来就想做**的事。
2. **`Fogg Maxim #2`**——帮人们**感受到**成功（注意是「感受到」，不是「获得」）。

作者的定位是：在帮别人改变时，把这两条当向导；守住它们，「大概已经站在了可靠的道德立足点上」。越出这两条（比如让人做他并不想做的事、「以『为你好』为由越过对方意愿」），就滑向**操纵**。

所以它是一张**防护栏**：不是教你怎么设计群体改变（那是 `group-behavior-design`），而是在你动手前拦一道——任何「帮助/影响他人」的方案，逐条过这两个问题，判它到底是「支持」还是「操纵」。

**本卡必须让人看见的一件事**：原书把这道护栏**建得很薄**。作者先用一句**免责前提**把「操纵」的指控挡回去——「我们其实一直在影响他人，只是多半没意识到」——然后把「最合乎道德的方式」收窄成「用最好的方法帮人，同时留意自己对人产生的影响」。**全书没有给出「同意」的判据**：没有说清什么时候必须取得告知同意、没有退出机制、没有处理「影响者与被影响者权力不对等」。这是整套方法论里**最该有边界却最缺边界**的位置。本卡在 E/B 两段把这条缺口的**补法**写出来，并明确它是**我们补的**、不是原书给的。

## A1 — Application Example

**案例（原书学员案例，`c62`，第08章）：迈克用咖啡机滤网改变儿子克里斯。**

- **输入/问题**：迈克想让 21 岁、被大学开除的儿子克里斯振作。他原来的做法是从「动机」施压——但推不动，父子关系紧张。
- **怎么执行**：迈克没有逼克里斯做他不想做的事（**`Fogg Maxim #1`** 要求帮人做其本来就想做的），而是把「维护咖啡机」拆到克里斯愿意做的第一步——用完把滤网放在吧台上；克里斯照做时，迈克**立刻道谢、帮他感受成功**（**`Fogg Maxim #2`**）。方案正是「支持」而非「操纵」：被测者没有被要求做超出其意愿的事，也没有在脆弱处被挑毛病。
- **结论/真实结果**：克里斯逐渐主动清洗并装回滤网，父子关系改善；后来找了两份兼职、为搬出去攒钱，父子关系达到自其出生以来最好。（原书交代了结果。）

**反例对照（说明性，供识别越界）**：作者在谈这条护栏时设想的情形是「管理者想让员工周末加班，理由是『帮』他们晋升」。逐条核对：员工本来想做的是周末休息，不是加班（`Maxim #1` 不过）；加班也谈不上让人「感受成功」（`Maxim #2` 存疑）→ 这是**越界/操纵风险**，不是支持。原书以此类情形说明「守住两条即站在道德基础上，越出即滑向操纵」，但**未展开同意判据**（见 I / B 段）。

## A2 — Future Trigger

**1）用户会在什么情境下遇到这类问题（3–5 条具体场景）**

- 你在帮别人或一个团队改变，动手前想确认「我这样算不算操纵 / 有没有越界」。
- 作为管理者/老师/家长，你想推一个改变（加班、加练、改习惯），担心是「为了他好」越过了对方的意愿。
- 你在设计一个面向用户或下属的「助推」，想知道底线在哪、要不要告知。
- 别人（或你自己的团队）已经开始用「行为设计」影响人，你想先上一道伦理护栏。

**2）语言信号（中英双写关键 trigger）**

- 中文：我这样算不算操纵 / 帮别人改变有什么底线 / 边界在哪 / 改变他人的伦理 / 「为他好」可以吗 / 要不要对方同意 / 帮人改变的道德底线。
- English: is this manipulation / how do I change others ethically / ethical guardrails for influencing people / helping vs manipulating / do I need consent.

**3）与相邻能力怎么区分**

- `group-behavior-design`（同册相邻）：那张卡回答群体设计**怎么做**；本卡回答这么做**有没有越界成操纵**。两者配合使用。
- `fogg-maxims-filter`（`cross_book`，`p97`）：与本卡**同源、同两条 `Fogg Maxim`**，但输出契约不同——本卡是「帮**别人**改变时会不会越界成操纵」的**护栏**；`p97` 是「**自己**采纳一套外界现成方案时要不要投入」的**准入过滤**。二者**只建链接不合并**（gate-c §3）。
- 来源路由入口 `fogg-behavior-model`：只在「了解整套模型」时触发。

**4）近邻负例（什么样的请求不该触发本卡）**

- **【vs `fogg-maxims-filter`】**「外界给我一套方案/工具/建议，我该不该采纳 / should I adopt this program」——这是**自己**当决策者去过滤外界方案 → **不触发本卡**，走 `fogg-maxims-filter`。
- **【vs 晋级技能】**「我自己想改掉熬夜 / 我该怎么养成跑步」——改变对象是用户**一个人** → **不触发本卡**，走对应晋级技能。
- **【vs `group-behavior-design`】**「帮我设计一套让团队每天站会的 7 步方案 / how to run a group habit program」——诉求是群体**设计流程**而非伦理裁决 → **不触发本卡**，走群体设计卡（设计时再回来过本卡）。

## E — Execution

**输入契约**

- 必需：一个具体的「要帮助/影响某个人或某群人的改变方案」，要能说清三件事——**对象是谁**、**想让 TA 做什么**、**用什么手段**。
- 缺任一项先问；不许静默假定对方意愿或你的职权。
- **判停**：若改变对象只是用户**自己一个人** → 本卡不适用（走晋级技能）；若诉求只是「某个外界现成方案要不要采纳」 → 转 `fogg-maxims-filter`。

**步骤**

1. **过 `Fogg Maxim #1`。** 问：这个改变，是不是 TA **本来就想做**的？写下「TA 想做的是什么」，并判断所求行为是否落在其中。
   - 完成标准：给出明确的「是 / 否」，且「TA 想做的」有据（不是你的假设）。
2. **过 `Fogg Maxim #2`。** 问：这个设计会不会让 TA **感受到**成功（而不只是「获得」成功）？指出设计中哪一步制造「成功感」。
   - 完成标准：指明方案里具体制造成功感的那一步（如即时庆祝/反馈）。
3. **越界判定。** 两条都过 → 在坚实道德基础上（作者的判据）；任一条不过（尤其「让 TA 做 TA 并不想做的事」「以『为你好』越过对方意愿」）→ 标记**越界 / 操纵风险**，回到 `group-behavior-design` 重设计。
   - 完成标准：给出「支持 / 越界风险」的明确判定。
4. **补同意与告知（★ 我们补的边界，原书未给）。** 判断该改变是否涉及对方的**知情与同意**：若对方不知情/未同意，说明**告知方式**与**退出通道**。
   - 完成标准：写下「是否需要告知 / 取得同意」的判定，以及具体做法（或写明为何不需要）。
5. **出结论。**
   - 输出契约：一份核对结论 = `{Maxim #1：过 / 不过}` + `{Maxim #2：过 / 不过}` + `{越界判定：支持 / 越界风险}` + `{同意与告知处理}`。
   **产出类型**：`diagnosis`（一次伦理核对判定）

## B — Boundary

**反场景（不要用本卡）**

- 只做「用户自己一个人」的行为改变时 → 走个人晋级技能，不经过本卡。
- 用户只是问「一套**外界**现成方案要不要采纳」 → 走 `fogg-maxims-filter`（`p97`），不要在本卡做准入过滤。
- 用户要的是群体**设计流程**而非伦理裁决 → 走 `group-behavior-design`。

**作者回避的问题（原书最缺边界处，正面对写）**

第 08 章「群体行为设计」**回避了「未经同意算不算操纵」**。作者的处理方式是：先用一句**免责前提**把问题挡回去——「我们其实一直在影响他人，只是多半没意识到」（`x48`）；随后把「最合乎道德的方式」定义为「用最好的方法帮人，同时留意自己对人产生的影响」；最后说，守住两条 `Fogg Maxim`「大概已经站在了可靠的道德立足点上」。**从这一步起，全书就不再回答「同意」的问题了**：没有说什么时候必须取得告知同意、没有退出机制、没有处理「影响者 vs 被影响者权力不对等」、也没有划出「产品化/大规模影响用户」与「私下帮一个人」的区别。我们在核验时与反例分区 `x48` 都已报过这一点——**这是整套方法论里最该有边界却最缺边界的位置**。

**我们补的使用边界（★ 标明是我们补的，不是原书给的）**

1. **同意分层**：对**成年人、有决策能力、且改变由你发起**的场景，默认要求**告知**（说明你在做什么、为什么、TA 可拒绝）；对**权力不对等**场景（上级对下级、老师对学生、家长对未成年子女）以及**产品化/大规模影响用户**的场景，把「告知 + 可退出」作为**准入前提**——不能因为「是帮 TA 做 TA 想做的事」就跳过。
2. **不伪装**：「忍者」式的不点破，只允许用于**降低摩擦的环境微调**，不允许用于**隐瞒真实目的**。对方若问起，须能如实说明。
3. **可退出**：任何群体改变都要给对方一个**无代价的退出通道**；不接受「退出要付出羞辱、惩罚或额外成本」。
4. **不得以「我一直在影响他人」当免责**：这句话是**事实陈述，不是伦理许可**；它恰恰说明影响无处不在，因此更需要边界。
5. **两条 maxim 不是充分条件**：过了两条 maxim 只说明「方向对」，**不等于**「已获同意」「不会伤人」。必须与上面 4 条一起用。

**证据 / 术语提醒**

- 本卡引用的「福格原则 1/2」，原书用词是 **`Fogg Maxim #1/#2`**（原书**无** `Fogg Principle`）。用「原则」会与原文的 Maxim（格言/准则）错位。
- `x48` 的 `who_warns` 是「作者自设边界」，但其 notes 已注明：原书对「缺少明确同意是否构成操纵」只轻描淡写，**未给同意判据**——引用时不要把它当成一条**硬的**伦理边界。

**相邻易混**

- `fogg-maxims-filter`（`cross_book`）：同源同两条 `Fogg Maxim`，**只建链接不合并**；区别见 A2（帮别人 vs 采纳外界方案）。
- `group-behavior-design`：本卡判越界，那张卡给做法；任何群体设计动手前应先过本卡。

## 相关能力

- **group-behavior-design**（组合）：那张卡给群体设计的「做法」，本卡判「这么做有没有越界」；群体设计动手前先过本卡。
- **fogg-maxims-filter**（对比）：同源、同两条 Fogg Maxim，但输出契约相反——本卡约束「我去影响别人时别越界」，它做「我采纳外界现成方案时的准入过滤」。
