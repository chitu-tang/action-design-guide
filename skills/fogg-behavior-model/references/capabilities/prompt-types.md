# 生活中常见的 3 类提示（人物提示 / 情境提示 / 行动提示）

## R — 出处（Reference）

本节方法论出自 B.J. Fogg《Tiny Habits》第 4 章（2020；中译《福格行为模型》）。原文依据保存在私有工作区（溯源条目 `f18`），不随公开版分发。

**术语注**：作者全书统一用「提示（Prompt）」，英文原词一律 `Prompt`——**不是 `trigger`**（旧版 B=MAT 的「触发」已被「提示」取代）。三类英文原词经英文原版回核为 `Person Prompt / Context Prompt / Action Prompt`（`t48`）。

## I — Interpretation

这段框架只做一件事：**面对一个新习惯，先决定"拿哪一类提示来提醒自己"**，并给出三类的优劣排序。

- **人物提示（Person Prompt）**——靠你自身内部的信号或记忆：生理本能（饿、憋尿）可靠，但"**自己记得**"这类不可靠。人的记忆出了名地靠不住（作者用一个漏掉邻居晚餐的故事说明）。→ **设计行为时应尽量避开。**
- **情境提示（Context Prompt）**——环境里的东西：便利贴、App 通知、闹钟、电话铃、同事提醒。它可以设计，但**对"养成长期习惯"不够可靠**——你未必在提示响起时有能力/在场，而且提示堆多了会让人**钝化**、对提示视而不见。→ 更适合**单次行为**（如预约看医生、赴约）。
- **行动提示（Action Prompt）**——把**一件已经在做的既有行为**当作提示。作者给它取别名 **Anchor（锚点）**，并认为这是**最好的提示类型**：既不依赖记忆，也不会因提示过多而钝化。

一句话骨架：**P（提示）可以来自"人 / 环境 / 既有行为"三者之一；可靠性排序是行动提示（锚点）最优 → 情境提示次之、且只宜单次 → 人物提示尽量避开。**

（本卡只到"选类型"这一步；把锚点与新习惯**匹配好**是 anchor-matching，把碎片等待当锚点是 meanwhile-habit，把烦人刺激当锚点是 pearl-habit。）

## A1 — Application Example

三类提示各有原书案例，可据此判断"该选哪一类"：

| 类型 | 原书案例 | nature | 原书结果 |
|---|---|---|---|
| 人物提示（失败） | 作者仅凭记忆赴新邻居鲍勃和雯达的晚宴（`c26`，第04章「1．人物提示」） | 原书亲历 | 「我把聚会搞砸了」，6:42 才从语音留言想起，再三道歉 |
| 情境提示（重新设计后成功） | 作者把每周一次的浇花/付账单改用「双休清单」：小标签贴贴在活页本 WEEKEND TASKS 页，周六放厨房柜台逐项贴走（`c27`） | 原书亲历 | 「这张清单让一切变得不同了」，能可靠完成清理冰箱、浇花 |
| 行动提示（成功） | 作者用「上洗手间」这个本能行为作提示，冲完厕所做两个俯卧撑（`c28`） | 原书亲历 | 「这个习惯我已经坚持了 7 年」，一天可达 50 个 |

**注**：三条均为作者自述、无对照样本量（幸存者偏差）。`c26` 是负例，`c27` 说明情境提示**必须重新设计**才可用，`c28` 是行动提示正例。

## A2 — Future Trigger ★

**1. 用户会在什么情境下遇到这类问题（3–5 条）**
- 已选定一个想做的行为，却不清楚"该拿什么提醒自己"：「这个习惯我该用什么提醒？」
- 之前靠闹钟/便利贴/记性提醒都失败：「我设了闹钟还是不做」「总是想起来时已经晚了」。
- 想比较几种提醒方式的可靠性：「用提醒 App 好，还是接在一件固定的事后面好？」
- 为**单次**行为选提醒（预约、赴约）vs 为**长期习惯**选提醒，需要区分。
- 提示太多、已经不响应任何提醒：「到处都是便签和通知，我现在全都看不见了」。

**2. 语言信号（中英双写）**
- 中文：提示 / 提醒 / 用什么提醒自己 / 设闹钟没用 / 便利贴 / 靠记性 / 三类提示 / 人物提示 / 情境提示 / 行动提示 / 锚点 / 提示太多没反应 / 是单次行为还是长期习惯。
- English: prompt / reminder / what should I use to remind myself / alarms don't work / sticky notes / relying on memory / three types of prompts / Person Prompt / Context Prompt / Action Prompt / anchor / prompt overload.

**3. 与相邻能力怎么区分**
- 统一口径：用户**只要解决「提示在哪」这一步** → 触发本类卫星卡；用户要**整体养成一个习惯** → 走 tiny-habit-design（第 5 步「找到'对'的提示」）。
- anchor-matching：本卡先决定用人物/情境/行动哪一类提示；锁定行动提示（锚点）后，锚点配不配走它。
- meanwhile-habit：同簇不同手法——本卡是三类提示全景，它是"碎片等待时间当锚点"这一变体。
- pearl-habit：同簇不同手法——它是"把负面刺激转成提示"的另一个变体。
- 来源路由入口 fogg-behavior-model：只回答"这套模型是什么、怎么系统性用"，不针对某个具体新习惯选提示。

**4. 近邻负例（什么样的请求不该触发本卡）**
- 「帮我把这个新习惯整体设计出来」→ 不触发本卡，走 tiny-habit-design（全流程）。
- 「我已经决定用锚点，这个锚点跟我这个习惯配不配？」→ 走 anchor-matching（只做锚点匹配三考量）。
- 「怎么把等电梯/排队的碎片时间利用起来养成习惯？」→ 走 meanwhile-habit（锚点变体）。
- 「怎么把一件烦人的事变成提示？」→ 走 pearl-habit（锚点变体）。
- 「我想戒掉睡前刷手机」→ 走 change-bad-habit-system（终止/替换，属"减"）。
- 「我为什么总做不到早起？卡在动机、能力还是提示？」→ 走 bmap-diagnosis（只要归因）。

## E — Execution

### 输入契约
- **必需**：一个**具体的、想反复发生的行为或想养成的新习惯**（如"每天用牙线""每天测血压""赴约"）；可附"是单次行为还是长期习惯"这一区分信息。
- **先做行为判别**（p20）：若输入是"变健康""减压"这类**愿望/成果**而非此刻可做的行为，先拆到一个具体行为。
- **可选**：过往提醒失败的记录（用了什么、怎么失效）。
- **缺**具体行为时先问，**不许静默替用户猜**。

### 输出契约

**产出类型**：`patch`（给已有设计换零件：提示类型）

针对该行为选定**一类提示**，并附：
1. 选定类型（人物 / 情境 / 行动提示）；
2. 选择理由（依赖记忆？会不会钝化？单次还是长期习惯？）；
3. 该类提示要避开的**失败边界**；
4. 若选行动提示（锚点）→ 明确转 anchor-matching 或交回 tiny-habit-design 第 5 步继续。

**完成标准**：用户能说出"用哪一类、为什么，以及这么选避开了什么失败模式"。

### 步骤
1. **固定目标行为与频次**：写下一个具体行为，并标注"单次 / 长期习惯"。
   - 完成标准：有一个此刻可做的具体行为，且已区分单次 vs 习惯。
   - 判停：若给的是愿望/成果 → 回输入契约先拆分。
2. **逐一评估三类提示**：对人物 / 情境 / 行动各问——①靠不靠记忆？②对长期习惯可靠吗？③会不会因堆太多而钝化？
   - 完成标准：三类都过了一遍，并记录各自的适配结论。
   - 判停：若是**单次行为**且用户已能可靠设提醒 → 情境提示即可，可停。
3. **选型并写理由**：给出选定类型；长期习惯默认指向**行动提示（锚点）**。
   - 完成标准：用户说出类型 + 理由 + 该类型要避开的失败边界。
   - 判停：若选行动提示 → 跳到 anchor-matching（匹配考量）或交回 tiny-habit-design 第 5 步；若该锚点属于碎片等待 → meanwhile-habit、属于负面刺激 → pearl-habit。

## B — Boundary

### 不要用（反场景，按分流）
- **要整体养成一个习惯（不止提示这一步）** → tiny-habit-design（全流程）。
- **已锁定用锚点，只需把锚点配好** → anchor-matching。
- **把碎片等待时间当锚点** → meanwhile-habit；**把烦人的负面刺激当提示** → pearl-habit。
- **诊断某行为为何没发生** → bmap-diagnosis。**戒掉/减少坏习惯** → change-bad-habit-system。
- **只想了解这套模型本身** → 来源路由入口 fogg-behavior-model。

### 作者警告过的失败模式（反例素材）
- **用情境提示养长期习惯** x19：日历/闹钟/便利贴/家人提醒做长期习惯的提示不可靠（作者亲历失败：浇花闹钟响起时他人在杂货店，那一刻他根本没法去做）。
- **用人物提示（靠记性）** c26：作者仅凭记忆漏掉邻居晚宴。
- **情境提示设太多 → 钝化** x20：提示越堆越多，大脑对所有提示脱敏，等于没有提示。
- **把提示交给运气** x22：不主动设计提示、指望环境或记性"碰巧"触发。

### 作者盲点与待核查（不许当规律用）
- 本卡只说"**选哪一类提示**"。至于"提示之后的固化机制"——作者主张**情绪（庆祝）而非重复次数**创造习惯（f26 / `p53`），以及"**演练 7–10 次即固化**"（f30）——**均为作者本人推测、缺可复核实验依据，且不在本卡职责内**；需要庆祝请走 celebration / tiny-habit-design 第 6 步，且不得把上述机制当已证实的普适规律。
- **安全阀缺失**：若用户的"提示问题"底层其实是**成瘾/物质依赖**（如戒酒、戒赌），本卡不适用——转 change-bad-habit-system 并提示该线**成瘾/自由落体型没有判停规则**（作者只写"交给专家"），须提示转介专业人士。

### 相邻易混
- anchor-matching：三类提示**选型** vs 锚点**匹配**。
- meanwhile-habit / pearl-habit：本卡选类型 vs 这两个锚点**变体**的具体落地。
- tiny-habit-design：单点（提示在哪）vs 全流程。

## 相关能力

- **tiny-habit-design**（组合）：养成全流程；本卡只管第 5 步里「提示选哪一类」这一步。
- **anchor-matching**（对比）：本卡先决定用人物/情境/行动哪一类提示；锁定行动提示（锚点）后，锚点配不配走它。
- **meanwhile-habit**（对比）：同簇不同手法——本卡是三类提示全景，它是「碎片等待时间当锚点」这一变体。
- **pearl-habit**（对比）：同簇不同手法——它是「把负面刺激转成提示」的另一个变体。
