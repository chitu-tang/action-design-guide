# 行动设计指南 — 产品入口

## 这个技能干什么

四步固定顺序，不要跳：**读档案 → 判层 → 路由 → 产出写回档案**。

它自己不讲书里的内容。书里的方法在各自的能力入口里，本技能只负责把用户的实际处境对到那一层，再把结果写回档案，让下一次不用从头开始。

## 触发与不触发

**适用**：用户带着**自己的执行事实**来，而且这件事要**接着往下走**——这段时间实际做了什么、那件事后来怎么了、断了想重启、要复盘一段执行、要把这次的设计记下来、不知道该用哪个方法。用户点名「行动设计指南」时同样适用。

**不触发（改走别处）**：

- **没带执行事实的单次方法询问**。判别线是**有没有执行事实**，不看你问的是一件事还是多件事。**「没做成」也算事实**：「我试了一个月，一想到备料就算了」（试过但失败）和「我想了两个月，一次都没开始」（想做但没动）都带着自己的处境，都归本入口；「怎么让一个行为变简单」只想要方法，本技能不代答，走那本书的能力入口。
- 只想弄清某本书里某个方法怎么讲、某本书说了什么 → 走那本书的能力入口，本技能不转述。
- **与行为改变无关的纯信息查询**（概念定义、书籍元信息、章节概览）→ 归对应那本书的能力入口：入口直接读它的 `references/` 回答，只是不加载任何能力卡。这是入口的活，不是本档案的活。

**先判停，再判层**：出现成瘾或物质依赖、躯体戒断风险、自伤意念、进食障碍、精神疾病诊断、结构性困境（贫困、人身安全）→ 只做转介，不出设计。

## 第 0 步：读档案

在工作目录下找 `.action-design/`：

| 情况 | 做什么 |
|---|---|
| 目录存在 | 读 `me.md` 与 `plans.md`，把「你正在做的设计」带进对话。**不要重新问一遍档案里已经记过的东西。** 要复盘时再读 `log.csv` 与 `reviews.md`。 |
| 目录不存在 | 走文末「首次使用：建档访谈」，谈完再往下。 |

**每次任务的第一步，不可跳过。** 不读档案就给建议，等于抹掉用户之前所有的工作。

档案内容不外发、不写进任何公开产物、不进仓库。当前目录是 git 仓库且 `.gitignore` 里没有 `.action-design/` 时，建档后补上这一条。

## 分层与定序

先判卡在哪一层，再按定序取**第一层能动的那一层**。

| 层 | 这一层回答什么 | 谁负责 |
|---|---|---|
| 环境层 | 把好行为的线索变显眼、把坏线索撤掉、让最省事的那个选项变成你想要的那个 | `atomic-habits`（线索侧）；默认值与摩擦的原则来源是选择架构，不单独出卡 |
| 阻力层 | 想做、做了也不难、提示也在，就是不肯动（惯性／费力／情感／抵触） | `human-element` |
| 能力层 | 把它变简单 | `fogg-behavior-model` |
| 提示层 | 挂到一个已经发生的动作上 | `fogg-behavior-model` |
| 情绪层 | 做完的那一刻让它感觉好 | `fogg-behavior-model` |
| 身份层 | 让它变成「我是谁」的一部分 | `atomic-habits` |
| 维持与进阶 | 已经做到之后：怎么加量、无聊了怎么处理、这个方向该不该换；以及一直坚持却不见进展 | `fogg-behavior-model`（`habit-growth`）／`atomic-habits`（`habit-mastery`、`goldilocks`、`find-your-field`） |

**阻力层只做定位与流程级动作，单个行为的降难度动作在能力层。** 同一句「费力」：先用四格或惰性轴判出是哪一维（不知道怎么做 = 模糊 / 步骤太多 = 消耗），再拿福格或原子的卡去降。两边接得住，不是二选一。

**环境层与提示层都落在 B=MAP 的 P（提示）这条线上，分界在这**：环境层改**静态配置**（东西放在哪、看不看得见），提示层改**时间锚点**（挂到哪个已经发生的动作上）。定序把环境排在提示前面：先动不花力气的布置，再动要挑时机的锚点。（分层表里环境层那句「让最省事的那个选项变成你想要的那个」属摩擦侧，和路由表「环境层 · 摩擦」那一行同轴，不在这条线上。）

**定序**：`环境 → 阻力 → 能力 → 提示 → 情绪 → 身份 → 维持与进阶`。从改环境到改自己，成本低、不依赖意志力的先动。最后一层不是「继续努力」，是「已经成了之后再动什么」：前六层都解决「怎么让它发生」，这一层解决「它已经发生了，接下来怎么办」。「**能动的那一层**」的意思见下节。

**追踪与复盘归 `atomic-habits` 的 `habit-tracking-reflection`，倚属环境层，不属阻力层取值域。** 遇到「我要记录／我要看自己断没断」时不要往阻力层里找。这条只管**记录这件事本身怎么做**（记什么、格式、断了要不要补）。记录已经做起来了、只是看着没感觉、不想再填、该不该继续，那是维持与进阶层的题，走 `goldilocks`。

**「已经做起来了」是维持与进阶层的准入门槛，也是它和诊断的分界线。** 坚持了几个月没断，只是往前没进展、问题多半在方法不在决心，别再按诊断题重走一遍 B=MAP。诊断层只接「根本没做起来、不知道卡在哪」的那种。

## 三条裁决规则

同一个问题两本书给不同答案时，按这三条判。**不要把两种说法并列摆出来让用户自己选。**

1. **诊断归诊断，干预归干预。** 判层分两步：**先用 B=MAP 的 P／A／M 找出缺了哪几格**（缺哪格就是哪几层的事），**再按定序从缺的层里取最靠前的那个**。三样都不缺、却还是不动，才落阻力层，用四格看拦在哪。两套不并列、不同时用——「想做却没动」这句话两套都套得上，上面的两步就是拿来把它分开的。**这套 P／A／M 只对「想做却没做」成立**：不想要的行为已经发生、要把它停下来时（戒掉睡前刷手机就是），没有「缺了哪一格」可找，B=MAP 诊断卡自己也不接这类请求——这种直接按定序从环境层往下取，不要硬套 P／A／M。干预侧（四定律、按摩擦类型对应的手段、选择架构）是一份清单，拿来出招。混在一起会把「定位」和「出招」搅成一团。
2. **用身份和结果当靶子选行为，用微小和庆祝当发令枪启动。** 两家的机制是同一个循环（小行为 → 成功感 → 身份），差别只在「先对自己说什么」。所以不选边：选行为时看身份与结果，启动时用微小与庆祝。
3. **选择架构降级为原则来源。** 它面向「给别人搭环境」，本工具面向个人。个人对自己用选择架构完全合法，但它的能力卡不单独出，只作为环境层的原则出处存在。

## 路由

判层之后按层加载对应能力。**具体加载哪张卡，一律读那本书自己的 `SKILL.md` 路由表，不要在这里另写一套。**

| 层 / 任务 | 加载（读这本书的 `SKILL.md` 挑卡） | 常落在哪张卡 |
|---|---|---|
| 环境层 · 线索 | `atomic-habits` | `cue-design`、`environment-design`、`habit-tracking-reflection` |
| 阻力层 | `human-element` | `four-frictions-diagnosis`、`friction-effort-diagnosis`、`streamlining`、`negative-emotion-source`、`resistance-self-persuasion`、`resistance-self-assessment`、`roadmap-clarity`、`referent-management` |
| 环境层 · 摩擦（与能力层同轴，去重时一起处理） | `atomic-habits`（`friction-prime`）／`fogg-behavior-model`（`make-it-easy`） | `friction-prime`、`make-it-easy` |
| 能力层 | `fogg-behavior-model` | `make-it-easy`、`tiny-habit-design` |
| 提示层 | `fogg-behavior-model` | `prompt-types`、`anchor-matching`、`meanwhile-habit`、`pearl-habit` |
| 情绪层 | `fogg-behavior-model`（`celebration`）／`atomic-habits`（`reinforcement`） | `celebration`、`reinforcement` |
| 身份层 | `atomic-habits` | `identity-design`、`find-your-field` |
| 先定位再出招（诊断） | `fogg-behavior-model`（`bmap-diagnosis`、`motivation-diagnosis`）／`atomic-habits`（`four-step-diagnosis`） | `bmap-diagnosis`、`four-step-diagnosis`、`motivation-diagnosis` |
| 改坏习惯 / 要分阶段方案 | `fogg-behavior-model`（`change-bad-habit-system`、`quit-habit-exercise`）／`atomic-habits`（`four-laws-inversion`） | `change-bad-habit-system`、`quit-habit-exercise`、`four-laws-inversion` |
| 维持与进阶（已经做到之后） | `fogg-behavior-model`（`habit-growth`）／`atomic-habits`（`habit-mastery`、`goldilocks`、`find-your-field`） | `habit-growth`、`habit-mastery`、`goldilocks`、`find-your-field` |

**这张表只列常落点，不是全集。** 池子里一共 54 张卡，表里没出现的（`deep-motive`、`temptation-bundling`、`reframe`、`golden-behavior`、`decisive-moments` 这些）照样适用：判层之后一律去那本书自己的路由表挑，不要因为表里没写就当作不适用。

**表里的「层」那几行是主路，「任务」那几行是补充，一个诉求两行都套得上时走「层」。** 用户只说了要什么结果（「我想把这件事戒掉」「我想让这件事别再发生了」，没说方法）→ 按层走，取第一层能动的，给一条最小动作；用户明说「试了好多办法都不行，给我一套完整的」「这事得分几步走」→ 才走「改坏习惯 / 要分阶段方案」那行。分阶段方案一次要交出三阶段（含新建一个习惯），跟「每次只动一件事」本来就冲突，不是用户点名要就不上。

**同一件事在「环境层 · 线索」和「环境层 · 摩擦」之间两读时，看用户问的是哪一面**：问「看得到什么 / 东西摆在哪儿」（手机就在床头）→ 线索侧 `environment-design`；问「这件事本身要几步 / 多难做」（拿手机得先走出卧室）→ 摩擦侧 `friction-prime`。同一个改动两个读法都讲得通时，按用户问的那一面挑，把挑的理由写进 `reviews.md` 的「依据」。**不要两张都加载**：同一件事只挑一张，另一面留给下次。

跨书真撞车时（反向四律 ⇄ 改坏习惯系统、两分钟法则 ⇄ 习惯生长、四步诊断 ⇄ B=MAP 诊断），**先按裁决规则 1 定位，再按定序出招**，并把这次的选择写进 `reviews.md` 的「依据」一行（那一行装两样东西：诊断的出处与排查过程，以及这次为什么在这两张卡之间选了它）。

## 动一件事之前，先看那段时间

判层之后、动手改之前，回档案核对一件事：**这件事发生在哪段时间，那段时间是怎么过的。** 这一步每一层都要走，跟这一层挑不挑锚点无关：它同时是判层的依据。

档案里那一段没有记录 → **先补问**（一到两问），问完补进 `me.md`，不要直接往下判。**「有节点、没过程」也算没有记录**：表里写着「23:30 洗漱完上床」，不等于记下了躺下之后那一个多小时怎么过的。补进去的位置是「一天的固定节点」那张表：新时刻就加行，已有行太粗就重写那一格的「我在做什么」，`可作锚点` 跟着重判。写动作，不写状态。

用户压根没指定这件事放在一天里的哪一段（「我想每天做二十个俯卧撑」）→ 「你想放在什么时候」本身就是那两问之一，别自己挑一个默认时刻就往下走。先按档案里最顺的既有动作给一个默认锚点，其余候选写进 `plans.md` 的「候选」字段，一并请用户确认。

**锚点只能从既有动作里挑。** 那段时间在档案里是空的，不等于用户那儿没有动作，多半是访谈时没问到。跳过这一步直接往下判，会得出「挂不上锚点」这种错结论。

补问之后那一段**确实**没有既有动作可挂 → 这是结论，不是失败。按卡自己的回流规则回到选行为那一步换一个（见 `anchor-matching` 第 2 步判停、`tiny-habit-design` 第 5 步判停），并如实告诉用户：**锚点选不出来，是这条路本身在告诉你该换目标。**

## 试过但没用的手段

用户说「这个我试过，没用」时，**不要直接换一张卡，也不要原样再来一遍**。这句信息量不够，先问清失败长什么样：

| 失败长什么样 | 怎么读 | 往哪走 |
|---|---|---|
| 压根做不到、试两天就忘了 | 这个手段没落到具体时刻，或者当时没有触发点 | 先补「何时／何地」的线索（`cue-design`），变成计划句再试 |
| 做到了，但嫌麻烦、后面就懒得做 | 动作本身要花力气。先分清「不知道怎么做」（模糊）还是「步骤太多」（消耗） | 模糊 → `roadmap-clarity`（补路径）；消耗 → 降难度：`make-it-easy`（缩行为）／`friction-prime`（改环境步骤）／`two-minute-rule`（缩到不可能失败） |
| 做到了，一点用没有 | 这一层不是病根 | 回到定序往下判一层 |
| 说不清 | 说不清本身就是信号 | 问清是哪一种失败（压根做不到 / 做到了没用 / 做到了麻炊得勍），别猜。**这里的「诊断」只管这个手段为什么失败，不是回过头重跑整套诊断**；实在问不出来就按定序往下判一层 |

**「已经试过并失败的那一层」不算「能动的那一层」。** 定序从头往下取，取的是还没试过、或者试过但当时做法不对的那一层。但要分清两件事：

- 试过的是**这一层的某个手段**（把手机放客厅），不等于**这一层本身**不行。同层还有别的手段（换场景、一室一用、撤掉充电器）。
- 所以先分辨是「手段不对」还是「层不对」。分辨不出来时按上表「说不清」处理。

**同层换手段最多试两次。** 同一层里连换两个手段都没用，就不再在这一层上磨，往下判一层，并把这次的判断写进 `reviews.md` 的「依据」一行。

**定序靠后的层试过、没用，不构成先跑诊断的理由。** 它只说明那一层的手段没落在对的地方（定闹钟是提示层的手段，不阻断环境层）；定序照样从靠前的、还没试过的那一层往下取，不要因为它「说不清」就先去诊断。

## 产出回写

能力卡上写的是抽象的产出类型，落到档案哪个字段在这里定。**产出必须落盘**——不落盘的诊断下次会重复一遍，用户会觉得这工具在原地打转。

| 产出类型 | 落到哪 |
|---|---|
| `design` | `plans.md` 新建一个计划块 |
| `program` | `plans.md` 新建一个分阶段块 |
| `patch` | 已有计划块的具名字段（提示／微行为／配方／技巧／庆祝／候选／加量退回，字段表见下节「档案格式」）。**还没有计划块时（首次设计就落到这类卡），直接新建一个块，把这几项填上。** |
| `diagnosis` | `reviews.md` 新增一条 |
| `none` | 不写档案 |

写 `log.csv` 只用四列：`date,plan_id,done,weak,note`。**只记正在执行的计划**：还没有计划块时不写；刚建块那天也不写，等用户报过第一次执行结果再记。`plan_id` 就用 `plans.md` 里的编号。`done` 填 `yes`／`no`。`weak` 填「今天最弱的那一环」，**单选**：动机／能力／提示／阻力／未知——**做没做到都能填**；做到了但某一步是勉强的，那一环就写在这里，没有明显弱环就留空。用户不写 `weak` 时按 `note` 事后反推，反推不确定就填「未知」，不要猜成一个确定值。

**写完档案要当面交接，别让档案替你说话。** 三件事说给用户听：

1. **下次什么时候来。** 用刚写进 `plans.md` 的「下次复盘」那个日期说成一句人话：「三天后，3 月 12 号左右，回来说一声就行。」
2. **回来时带什么。** 「这几天做了什么、哪一次没做到。」不带记录也能复盘。
3. **想记的话怎么记。** 愿意就一天一行、睡前填、十秒；断一天不用补。不愿意就说清楚这是可选的。

**记录可选，约定不可选。** 用户说不记就不再提；不事后追问「你记了吗」，也不因为表是空的就跳过复盘。

**同时进行的设计不超过 3 个。** 到上限时先问要不要收掉哪一个，不要直接开第四个。

## 档案格式

四份文件的名字与结构固定，照下面写，不要自己另拟。**建档时四份一起建出来**，还没有内容的那几份按本节末尾「零条目态」写。`me.md` 建档时全量写一次，之后按补问添补；`plans.md` 与 `reviews.md` **只追加、不改旧条目**——计划有变动，在那个块里加一行「改动史」，不要覆盖原来的字段。

表里用不上的单元格**留空**，不要写「无」「—」「否」这类占位。

### `me.md`

```markdown
# 关于我

## 一天的固定节点
| 时刻 | 我在做什么 | 可作锚点 |
|---|---|---|
| 07:30 | 起床，洗漱 | ✓ |
| 08:10 | 出门通勤 | ✓ |
| 08:40 | 到公司 | ✓ |
| 12:00 | 午饭，饭后在楼下走一圈 | ✓ |
| 18:30 | 下班，到家换鞋 | ✓ |
| 19:00 | 吃完晚饭，收拾厨房 | ✓ |
| 20:00–23:30 | 看剧、刷手机 | |
| 23:30 | 洗漱完上床 | ✓ |

## 环境与约束
- 工作时间：
- 家里有谁：
- 常待的地方：
- 手边常有的东西：

## 我能投入的
- 每天可支配：__ 分钟
- 愿意额外付出的精力：低 / 中 / 高

## 历史
| 试过什么 | 结果 | 我当时觉得卡在哪 |
|---|---|---|

## 硬停线
- [ ] 成瘾史 / 精神疾病诊断 / 结构性困境（贫困、人身安全）
      勾上：只做转介，不出设计。

## 我想成为什么样的人（可留空）
```

`可作锚点` 勾的是能当锚点用的节点。两条同时满足就勾：

- **它本身是一件有始有终的具体动作**——到达类的瞬间（到家、到公司）算，它有一个可识别的收尾；一整块时间不算（「看剧、刷手机」这种时段不勾）。
- **每天都会发生**——隔几天才来一次的（周会、临时的事）不勾。

时刻偶尔浮动**不影响**：「一般六点下班，偶尔加班到九点」照样勾，加班那天不用它就行。「我在做什么」写动作，不写状态。

**「历史」那张表是活的**：建档时填一次，之后用户运行时又想起一个旧失败手段，照样补进去。它是防重复设计的清单，不补就会重复同一个设计。

### `plans.md`

一个计划一个块。同一套块结构装两种体量，靠可选字段区分。

```markdown
## P001 · 晚饭后走十分钟              ← 单行为
- 设计于：2026-03-02
- 提示：收拾完厨房（行动提示 / 已收紧到收尾动作）
- 微行为：穿上鞋出门
- 配方：在我收拾完厨房之后，我会穿上鞋出门
- 技巧：把鞋摆在门口
- 庆祝：回来时心里说一句「成了」
- 候选：晚饭后走 / 午饭后走 / 通勤提前一站下
- 加量 / 退回：状态差就走五分钟
- 判停条件：连着三天在外吃饭，说明锚点不合适，回来找我
- 状态：进行中 / 已固化 / 已放弃
- 下次复盘：2026-03-12
- 改动史：2026-03-09 把锚点从「吃完晚饭」换成「收拾完厨房」

## P002 · 减少下午的含糖饮料          ← 分阶段方案
- 设计于：2026-03-15
- 类型：三阶段方案
- 阶段 1：在我吃完午饭回到工位之后，我会先喝完水杯里的水
- 阶段 2：具体坏习惯清单 + 逐项干预 + 无效回退
- 阶段 3：替换配方（含重映射提示）
- 状态：阶段 1 进行中
- 下次复盘：2026-03-22
- 改动史：
```

**为什么留着「技巧 / 庆祝 / 候选 / 加量退回」这几个字段**：这几样产出不是新计划，而是给已有计划换零件。没有这些字段，它们就无处可写，复盘时整条链断掉。

**换零件类的卡产出「清单」时，整份写进「技巧」一行**：环境改造（充电器挪出卧室、把鞋摆在门口）、预备动作、一次性布置这类不动行为本身、只动布置的动作都归这里。不要另开字段，也不要拆成新计划块。

两种体量共用同一套字段名。一个块里只写这次用到的字段，用不上的整行省掉。

**「下次复盘」由你定，且要说给用户听。** 不要留空，也不要写「待定」：首次计划一般定在三天到一周后。写进档案不等于约定——档案用户看不到。

### `log.csv`

字段**必须少**，这是记录能活下来的前提。

```
date,plan_id,done,weak,note
2026-03-02,P001,no,能力,加班到十点，厨房没收拾
2026-03-03,P001,yes,提示,做到了，但得靠想起来
```

- `done`：`yes` / `no`
- `weak`：**今天最弱的那一环**，单选：动机 / 能力 / 提示 / 阻力 / 未知。
  **做没做到都能填**：没做到时它就是原因；做到了但某一步是勉强的，那一环也写在这里；没有明显弱环就留空。
- `note`：一句话，可以空。

### `reviews.md`

每次复盘一条。

```markdown
## 2026-03-10 · 复盘 P001
- 判定：缺**能力**（提示在、动机在，穿鞋这一步做不到）
- 依据：`bmap-diagnosis`，按 P → A → M 顺序排查；三条记录里两次 `no`、一次 `yes`
- 改动：微行为从「穿上鞋出门」降到「穿上鞋」
- 下一步看什么：连着三天穿好鞋却没出门，说明问题不在能力，回来重判
```

**为什么必须落盘**：诊断结论不记下来，下次复盘会重复同一个诊断，用户会觉得这工具在原地打转。

抬头两种写法。**复盘条**写 `## 2026-03-10 · 复盘 P001`，用于已经跑过一段的计划。**诊断条**写 `## 2026-03-10 · 诊断（这件事）`，不带 `P` 编号，它讲的是「怎么定下来的」，不是复盘；**首次设计落到 `patch` 类卡、当场新建计划块时，也照样写一条诊断条**（产出回写表里 `patch` 那行只管计划块，不代表就不用写这一条）。诊断条同样填四项，没动作可改时「改动」写「无（先补问 / 先定位）」，「下一步看什么」写清还差哪一块信息就能往下走。

### 零条目态

建档时四份一起建出来，还没有内容的那几份这样写，**不要省略不建**（第 0 步读档案时假设四份都在）：

- `plans.md`：空文件
- `reviews.md`：空文件
- `log.csv`：只留表头一行 `date,plan_id,done,weak,note`

`.gitignore` 只在**当前目录是 git 仓库、且里面没有 `.action-design/` 这一条**时补。不是 git 仓库就不建。

## 不做成打卡 App

无积分、无连续天数、无排行榜、无落后百分比。记录只服务诊断——`log.csv` 是给复盘用的证据，不是成绩单。

**记录是可选项，不记不影响复盘。** `log.csv` 是空的照样走：先用追问把这段时间补出来（「这几天做了几次、哪一次没做到、当时什么情况」），再照 `reviews.md` 的四项写一条。空表不是失败的复盘，靠回忆补出来的诊断一样能落盘。用户不记时不要露出「你应该记」的意思。

「已放弃」是正常出口，与「已固化」平权，复盘时主动问，不要等用户自己开口。

## 加载规则

- 每次任务：读本文件 → 读档案 → 判层 → 读对应那本书的 `SKILL.md` → 按它的路由表加载 **1** 张卡。
- **「1 张卡」是「一次只动一个地方」，不是「不许换卡」。** 卡自己的判停线把你转到前置诊断或下游的卡时，跟着它走：先做完那一步、把结论落盘，再接着加载。诊断卡（`four-frictions-diagnosis`、`bmap-diagnosis`、`four-step-diagnosis` 这类）**不产出动作**，它们只给分类和去向，去向那张卡要接着加载。
- 不要一次把整条流水线跑完。**每次只动一件事：一条计划、最多一个动作。** 卡产出的是配方（微行为 + 锚点 + 庆祝），那算一件事，可以一次给全；环境改造这类卡的产出是**一份清单**，清单里的多条只要指向同一处、同一次，同样算一件事；但不要同时开第二条计划，也不要把别的层的东西顺手塞进去。给完就停，等用户执行完回来。
- 判不出层时，先问一个能分辨层的问题，不要六个层各给一条建议。

## 边界与判停

- 描述里出现成瘾、躯体戒断风险、自伤意念、进食障碍、精神疾病诊断 → 立即停止设计，转为建议寻求专业帮助，并记进 `me.md` 的「硬停线」。
- 用户没给出可操作的具体行为（哪个行为、什么场景）时，先停下要求具体化，不静默猜值。
- 用户要把结论当既定规律用（某个数字、某条「做多少次就固化」的说法）时，说清这是作者主张还是实证，不替书打包票。
- 用户要求把档案内容贴到公开场合时，先确认再动手。

## 首次使用：建档访谈

找不到 `.action-design/` 时跑一次，**不超过 10 问**，只问会改变判断的那些。谈完**由你落笔写 `me.md`**，不要让用户自己填表。

必问：

1. **一整天的形状**——从起床到躺下，每一段在做什么，具体到时刻（锚点要从这里选）。不要只问起床、通勤、午休、睡前这四个点：**要动的那个行为多半落在剩下的时段里**。下班到家到躺下那一段单独问，它常常是全天最大的一块。
2. 环境约束——几点下班、家里有谁、常待的地方、手边常有什么
3. 每天能支配多少分钟
4. 愿意额外付出的精力——低／中／高（没有刻度，「微小」就没有意义）
5. 以前试过什么、结果怎样、当时觉得卡在哪（不知道就会重复同一个设计）
6. **硬停线**——成瘾史、精神疾病诊断、结构性困境

可留空：想成为什么样的人。

硬停线勾上 → 只做转介，不出设计。

建完档：写下四份档案文件（`me.md` 全量，另三份按「档案格式」的零条目态）、按上面那条规则处理 `.gitignore`、用一句「我记下了什么」把档案复述给用户确认，再问这次想动哪件事。
