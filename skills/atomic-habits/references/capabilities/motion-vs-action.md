# 运动 vs 行动（motion vs. action：从「准备」转入「练习」）

## R — 出处（Reference）

本节方法论出自 James Clear《Atomic Habits》第 11 章（2018；中译《原子习惯》）。原文依据保存在私有工作区（溯源条目 `f42`、`f44`），不随公开版分发。

## I — Interpretation

「运动 vs. 行动」是一把**诊断尺**：判断自己到底是在推进一件事，还是只在原地打转。

- **运动（motion）**：计划、研究、学习、列清单、比较方案。它感觉像在前进，却**不产出任何结果**。
- **行动（action）**：真正会交付结果的行为——写出一篇文章、吃下一顿健康餐、完成一次训练。

作者的核心判断是：运动本身不产生结果，**只有行动产生结果**。而运动往往是**拖延的伪装**——它让你在不冒「失败、被评判」风险的前提下，获得「我在进步」的错觉；滑入运动的头号原因，就是**想把失败往后拖**。

所以本卡不是「禁止计划」，而是三步：**先辨认**手头在做的事属于运动还是行动；**再判断**它是否已经从「必要准备」滑成「拖延」（作者的判据是：准备一旦变成拖延）；**然后强制切换**——定义一条今天就能做、会产出可交付结果的最小行动，并接受它不完美。

它的取向是把重点从「准备」移到「练习」：你想做的是练，而不是只计划。这与作者同章的 `p63`（掌握习惯的关键是「从重复开始，而非从完美开始」）与 `p64`（最有效的学习是练习而非计划）是同一条线。本卡管的是「你现在这一步属于哪一类、要不要切」，**不管具体怎么把门槛降下来**（那是 two-minute-rule）。

## A1 — Application Example

**主例 · Uelsmann 摄影课的「数量组 vs 质量组」**（`c59`／`x17`，**原书转述的二手案例**）

- **输入/问题**：佛罗里达大学教授 Jerry Uelsmann 在摄影课第一天把学生分成两组——「**数量组**」按交照片的数量评分（交 100 张得 A，90 张 B，80 张 C……），「**质量组**」只需交**一张**，但要求近乎完美。
- **怎么执行**：数量组被迫不断按下快门、反复实拍、在暗房里试各种方法并从错误中学习；质量组则整天坐在一起**推测、空想**什么是完美。
- **结论/输出**：期末所有**最好的照片都出自「数量组」**；质量组只留下未经验证的理论和一张平庸的作品。
- **机制**：技能靠**重复与试错**（行动）长出来，不靠空想最优方案（运动）。
- **成色**：英文版注释记为 Bayles & Orland, *Art & Fear*, p.29（Orland 邮件确认本书为 adapted version）——**二手转述、且有改编，非原始研究**。

**原书自举例（作者用来说明 motion / action）**（`f42`）：列 20 个文章选题＝运动，真正写出一篇文章＝行动；搜索更好的饮食方案、读几本营养书＝运动，真正吃下一顿健康餐＝行动。

**作者自陈（本章开场）**：人们容易陷在「为改变找最优方案」里（最优的减肥法、最好的增肌计划、最棒的副业点子），结果迟迟不动手——他引伏尔泰「追求最优会妨碍做好」来说明「追求最优」本身可能就是不动手的原因。

## A2 — Future Trigger ★

**1. 用户会在什么情境下遇到这类问题（3–5 条）**

- 为一件想做的事**准备了很久**——查资料、买装备、报课程、列了一堆点子——却迟迟没有产出。
- 总在**找「更好的方案 / 更全的工具 / 更优的路线」**，选来选去就是不开始。
- 明明感觉一直在**进步、很忙**，回头却交不出任何可展示的东西。
- 想开始写点什么 / 做副业 / 健身，反复停在「研究阶段」、不敢出手。
- 自问「我到底是不是在拖」，或被人提醒「你只是在准备」。

**2. 语言信号（中英双写）**

- 中文：一直在准备 / 一直在研究 / 计划了很久 / 还没真正开始 / 总在找更好的方案 / 感觉在进步但没结果 / 这是不是拖延 / 我是不是停在准备阶段 / 光计划不行动。
- English: stuck in planning / keep researching / in motion not action / motion vs action / preparing instead of doing / procrastinating by planning / never get around to it / analysis paralysis.

**3. 与相邻能力怎么区分**

- decisive-moments：本卡判定「你整体**停在准备态**」；它处理「一天里哪几个**岔路口**决定走向」。
- two-minute-rule：本卡识别「卡在准备 vs 行动」；它给「**入口门槛太高**」时把行为缩到两分钟的具体工具。
- friction-prime：本卡问「你是在准备还是在行动」；它改「这件事**本身多难做**」。
- four-step-diagnosis（/ 福格 `bmap-diagnosis`）：要**完整归因**「卡在提示 / 渴望 / 反应 / 奖赏哪一环」→ 走它们。

**4. 近邻负例（什么样的请求不该触发本卡）**

- 「我想开始但根本起不来，给我一个两分钟的起始版」→ 走 **`two-minute-rule`**（不是判准备 / 行动）。
- 「我每天回家那个点总是不知不觉就瘫沙发、点外卖」→ 走 **`decisive-moments`**（岔路口的选择）。
- 「这个习惯做起来太麻烦、步骤太多」→ 走 **`friction-prime`**（改难度，不缩小行为）。
- 「我为什么总做不到早起，卡在动机还是提示上？」→ 走 **`four-step-diagnosis`**（/ 福格 `bmap-diagnosis`）。
- 「帮我把一个大目标拆成一个具体行为」→ 走福格 **`tiny-habit-design`** / `golden-behavior`。
- 「这套模型是什么、怎么系统性用」→ 走来源路由入口 `atomic-habits`。

**分流句（本卡 ↔ 相邻两卡）**：分不清自己是在「**准备**」还是在「**行动**」→ **`motion-vs-action`**；每天几个**岔路口式的小选择**（点外卖 vs 做饭）→ **`decisive-moments`**；**入口门槛太高、根本起不来**（要一个两分钟起始版）→ **`two-minute-rule`**。

## E — Execution

### 输入契约

- **必需**：①一个**想达成的结果**（例：写完一篇稿、开始健身、开副业）；②用户**当前正在做的事**的清单或描述（用来判断是运动还是行动）。缺「当前在做什么」时**先问**，不许静默替用户猜。
- **可选**：已经投入了多久 / 多少准备、是否有一拖再拖的经历。
- **适用条件**：用户的问题是「一直在准备、没有产出」。若真正的问题是「入口太大」→ 按 B 段分流到 two-minute-rule；若「太麻烦」→ friction-prime。

### 输出契约

**产出类型**：`patch`（给已有计划换零件：把「准备项」替换为一条会产出结果的行动；并附带运动 / 行动态判定）

- ① 对用户当前做的事，逐条给出「**运动 / 行动**」的判定（依据：会不会交付一个可检验的结果）；
- ② 若判定整体停在运动态，给出一个**动因**（是否在延迟失败 / 逃避被评判）；
- ③ 一条**今天就能做、会产出可交付结果的最小行动**（接受不完美）。

**完成标准**：用户能指出「我现在做的这些里，哪些是运动、哪些是行动」，并拿到一条当天可执行、能产出实物 / 可检验结果的动作。

### 步骤与完成标准

1. **逐条给「当前在做的事」打标**：把用户为这个目标做过的事列出来，逐条问「这一步会不会产出可检验的结果？」。
   - 完成标准：每条得到一个「运动 / 行动」判定，且判定理由指到「有无可交付结果」。
2. **判定整体状态 + 找动因**：若行动项为零或极少 → 判「停在运动态」；并看是否在**延迟失败 / 逃避被评判**。
   - 完成标准：给出「在运动 / 已在行动」的判定，并在运动态时点出一个动因。
3. **强制切换成一条行动**：定义一个**今天就能做、会交付结果**的最小动作，明确接受它不完美（呼应「从重复开始，而非从完美开始」）。
   - 完成标准：产出一条可当天执行、能产出实物 / 可检验结果的动作；用户能说出「做完它就算出了结果」。
   - 判停：判定用户其实是「**入口太大、根本起不来**」→ 转 **`two-minute-rule`**；若问题是「**步骤太多 / 太麻烦**」→ 转 **`friction-prime`**。

### 判停点

- 第 1 步后发现问题是「一天里几个岔路口的选择」→ 转 **`decisive-moments`**。
- 第 3 步若是「入口太大」而非「准备成拖延」→ 转 **`two-minute-rule`**。
- 需要完整归因（卡在四步哪一环）→ 转 **`four-step-diagnosis`**（/ 福格 `bmap-diagnosis`）。

## B — Boundary

### 不要用（反场景，按分流）

- 要「把入口缩到两分钟 / 用户根本起不来」→ two-minute-rule。
- 要处理「一天里几个岔路口式的小选择」→ decisive-moments。
- 问题是「这件事本身太麻烦 / 步骤太多」→ friction-prime。
- 要完整归因「卡在提示 / 渴望 / 反应 / 奖赏哪一环」→ four-step-diagnosis（/ 福格 `bmap-diagnosis`）。
- 只想了解这套模型本身 → 来源路由入口 `atomic-habits`。

### 作者警告过的失败模式（反例素材）

- **把「准备 / 计划」当成「行动」**（`x05`）：查资料、列点子、比较方案都是运动，感觉像在进步却不产生结果；作者明说滑入运动常是因为**避免失败与批评**。→ 这是本卡的核心反模式。
- **空想完美、减少实练**（`c59` / `x17`）：「质量组」只交一张却整天空想完美，最终只剩未经验证的理论和一张平庸作品。→ 追求完美规划而减少实际练习，技能不升反降。

### 作者盲点与待核查（缺口）

- **「准备到何时算拖延」原文未给判据**：`f44` 只给出「当准备变成一种拖延时，你就得改变点什么」，**没有**给出「到了哪一步 / 熬了多久就算拖延、该强制切换」的量化阈值。判定只能靠当事人自觉。**原书未给这条门槛。**
- **「重复多少次才够」同样未给**：本章另主张「掌握习惯的关键是从重复开始，而非从完美开始」（`p63`），但全书**未给**「需要多少次重复」的具体次数（task-08 已标注此缺口）。
- **不是一刀切禁令**：原文在同一处先声明运动有时也有用，计划 / 学习本身有合法用途。**不得**把本卡讲成「凡计划皆拖延」——它只在「准备已滑成拖延」时才要求切换。

### 相邻易混

- decisive-moments：本卡判「整体是否停在准备态」，它处理「一天里哪几个岔路口决定走向」。
- two-minute-rule：本卡识别「卡在准备」，它提供「入口太大」时的两分钟阈值与门户习惯。
- friction-prime：本卡问「你在准备还是在行动」，它改「这件事本身多难做」。
- four-step-diagnosis（/ 福格 `bmap-diagnosis`）：完整归因走它们。
- 福格 `tiny-habit-design`：要「缩小规模 + 锚点 + 庆祝」的完整养成流程走它；本卡只判「运动 / 行动」。

## 相关能力

- **two-minute-rule**（对比）：本卡判「在准备还是在行动」；「入口太大、起不来」走它。
- **friction-prime**（对比）：本卡问「是不是停在准备」；它改「这件事本身多难做」。
- **decisive-moments**（对比）：本卡判整体状态；它处理「一天里几个岔路口式的小选择」。
